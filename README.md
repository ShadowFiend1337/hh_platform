# predel

Платформа подбора ИТ-специалистов с подтверждением специализации и грейда через опрос и тестирование. Работодатель описывает потребность, находит кандидатов и отправляет персональное приглашение с зарплатной вилкой; публикация вакансии для этого не требуется.

## Текущий статус

Главная страница сохраняет дизайн из предоставленного архива: плавающую шапку, синий акцент, изображение брелоков и исходную композицию. «Попробовать» открывает интерфейсный прототип кабинетов работодателя и кандидата: подбор, фильтры, профили, тестирование и приглашения. Внизу сайта размещены логотипы из шаблона презентации ФСП.

Новый кандидат начинает с анкеты: отрасль, роль, специализация, самооценка грейда, стек и опыт. Общий стаж и места работы с задачами показаны отдельно. Если итог не написан в резюме, стаж рассчитывается по периодам работы; пересекающиеся месяцы учитываются один раз. Неверные периоды остаются в истории, но исключаются из расчёта с предупреждением; даты только с годами дают верхнюю оценку. Блок софт-скиллов убран из интерфейса; эта часть требований кейса пока не покрыта. После анкеты кандидат проходит тест; подтверждённая категория появляется только при успешной серверной попытке. В каталоге 146 вымышленных демонстрационных профилей; их результаты тестов и достижения явно помечены как демонстрационные.

В анкете 14 специализаций: Frontend, Backend, Fullstack, мобильная разработка, ML и Data Science, аналитика и инженерия данных, DevOps/SRE, тестирование, информационная безопасность, UX/UI, бизнес и системный анализ, управление продуктом, Embedded и электроника. Для каждой есть отдельные программы пяти грейдов: Стажёр, Junior, Middle, Senior, Lead. Доступны 25 отраслей; списки одинаковы в анкете, профиле и поиске. Импорт резюме распознаёт явно указанную роль и грейд, а стек фильтров подбора учитывает выбранное направление. Стаж сам по себе не назначает грейд.

«Прикрепить резюме» заполняет анкету из PDF, DOCX, текста или изображения. Сначала читается текст документа; для сканов работает локальный OCR на русском и английском. Страницы с крупными растровыми изображениями распознаются даже при наличии текстового слоя, чтобы неполная шапка не скрывала остальной опыт. Кандидат проверяет результат, дополняет недостающие сведения и отдельно даёт согласие. Достижения, образование, проекты, языки и портфолио сохраняются в профиле. [Требования и приватность](docs/resume_requirements.md).

Импорт проверен на четырёх предоставленных PDF, изображении страницы резюме и синтетических PDF/DOCX/сканах. [Фактические результаты](docs/resume_validation.md).

Тесты формирует и проверяет FastAPI: ключи ответов отсутствуют в браузере, попытки и результаты сохраняются через SQLAlchemy в локальной SQLite или PostgreSQL. В блоке «По вакансии» можно выбрать пример своей программы или вставить своё описание; структура программы сохраняется, показываются непокрытые требования. [Проверка механики](docs/assessment_validation.md) отделена от ещё не проведённой калибровки на кандидатах.

Поиск работодателя в переносимом FastAPI-backend использует текст профиля и структурные фильтры: зарплату, город, стаж, занятость, язык, портфолио и балл теста. Ответ поиска содержит предупреждение, что семантическая модель не подключена. Материалы эксперимента с RuBERT-tiny2 сохранены отдельно в `ml/` и [отчёте](docs/semantic_model.md), но не запускаются FastAPI-сервисом.

Профили, анкеты, компания, сохранённые подборки, приглашения и результаты находятся в FastAPI-хранилище. По умолчанию это локальная SQLite `backend/data/hh_platform.sqlite3`; при заданном `DATABASE_URL` используется PostgreSQL. Браузер хранит локальную копию и незавершённые ответы. Версии состояния защищают от незаметного перезаписывания в другой вкладке; сохранённые анкеты API разрешает только добавлять. Контакты выдаёт отдельный API только владельцу профиля или отправителю принятого приглашения при действующем согласии. Регистрация требует принятия актуальной версии политики и подтверждения email. После входа аккаунт открывает свои данные на другом устройстве через защищённую HttpOnly-сессию; в политике конфиденциальности доступно удаление аккаунта и связанных данных.

## Запуск

Нужны Node.js 24 или новее и Python 3.11 или новее. Скопируйте `.env.example` в `.env`, затем создайте и активируйте виртуальное окружение Python:

~~~bash
cp .env.example .env
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r backend/requirements.txt
npm ci --prefix frontend
npm run dev
~~~

`npm run dev` запускает Vite на http://127.0.0.1:5173 и FastAPI на http://127.0.0.1:8787. Перед отправкой писем укажите в `.env` параметры SMTP: `SMTP_HOST`, `SMTP_PORT`, `SMTP_TLS`, `SMTP_USER`, `SMTP_PASSWORD` и `SMTP_FROM`. Для типичного SMTP на порту 587 используйте `SMTP_TLS=starttls`; для 465 — `implicit`. В локальной разработке без SMTP код выводится только в журнал FastAPI; при `APP_ENV=production` регистрация вернёт ошибку до настройки почты.

Откройте http://127.0.0.1:5173. «Создать аккаунт» открывает регистрацию с выбором роли, а «Войти» возвращает к сохранённому кабинету. Примеры и форма подбора на главной остаются демо-входом. У аккаунта роль зафиксирована при регистрации; в демо её можно переключить в правом верхнем углу. Для проверки приглашений сначала пройдите анкету и тест, включите публикацию своего профиля, затем отправьте ему приглашение из кабинета работодателя.

### PostgreSQL через Docker Compose

Локальный режим не требует PostgreSQL. Чтобы использовать PostgreSQL, задайте `POSTGRES_PASSWORD` в `.env`, поднимите контейнер и замените `DATABASE_URL` адресом PostgreSQL:

~~~bash
docker compose up -d postgres
~~~

Пример URL: `postgresql://hh_platform:ваш_пароль@127.0.0.1:5432/hh_platform`. FastAPI создаёт текущую схему при старте. Сборка интерфейса: `npm run build`; `npm start` запускает FastAPI и раздаёт готовый сайт на http://127.0.0.1:8787. Подробнее — в [инструкции FastAPI](docs/fastapi_migration.md) и [описании backend](server/README.md).

Подробности реализации и границы прототипа — в [описании интерфейса](docs/interface.md).
