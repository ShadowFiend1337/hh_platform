# Интерфейс predel

React, TypeScript и Vite. Главная страница на `/` сохраняет дизайн из архива. Регистрация и вход открываются на `/auth`; выбранная роль и текущая вкладка кабинета находятся в URL. После подтверждения почты пользователь попадает в кабинет своей роли. Примеры и форма подбора на главной сохраняют демо-вход. API, тестирование и сохранение данных обслуживает Node.js из `server/`; браузер хранит копию состояния.

Перед кабинетом пользователь создаёт аккаунт: выбирает роль, указывает имя или компанию, логин, email и пароль, затем подтверждает email одноразовым кодом из письма. Анкета кандидата собирает отрасль, профессиональную роль, специализацию, самооценку грейда, стек и опыт. Категория подтверждается только успешным тестом; публикация профиля включается отдельно.

Над анкетой расположен импорт резюме. PDF.js читает PDF и растеризует сканы для Tesseract.js; Mammoth извлекает текст DOCX. Русская и английская модели `tessdata_best`, worker и WebAssembly размещаются на том же сайте. OCR выполняется в браузере; оригинал файла и полный текст не сохраняются и не передаются сервисам. Неоднозначные или отсутствующие поля кандидат заполняет вручную. Достижения видны сразу; образование, места работы, языки, портфолио и другие необязательные поля свёрнуты. Ссылка под согласием открывает `/privacy`, сохраняя черновик анкеты.

После чтения отдельная кнопка «Удалить резюме» рядом с заменой файла очищает прикрепление и сообщения импорта, сохраняя поля анкеты и ручные изменения. Во время чтения доступна отмена.

## Запуск из корня репозитория

~~~bash
cp .env.example .env
npm ci
npm ci --prefix frontend
npm run dev
~~~

Нужен Node.js 24 или новее; для локального семантического поиска также нужен Python и подготовленная модель по [инструкции сервера](../server/README.md). Адрес интерфейса: http://127.0.0.1:5173. API: http://127.0.0.1:8787. `npm run dev` из корня запускает Vite и сервер Node.js.

~~~bash
npm run build
npm start
~~~

Собранный сайт вместе с Node.js доступен на http://127.0.0.1:8787. Vite proxy `/api` используется при разработке. Сервер раздаёт `frontend/dist` для `/`, `/app`, `/auth` и `/privacy`.

### Данные и регистрация

Основной сервер хранит данные в SQLite под `server/data/`. Новый аккаунт получает отдельный кабинет; гостевой черновик в него не переносится. Перед чтением кеша проверяется аккаунт. При смене аккаунта локальный кеш очищается, а серверная identity в заголовке `X-Platform-Identity` запрещает запись старой вкладки другому пользователю. Роль подтверждённого аккаунта сохраняется при навигации и входе с другого устройства.

Для настоящих писем настройте SMTP в `.env`. В локальном режиме без SMTP письмо не отправляется: код записывается в исключённый из Git файл `server/data/mail.log`. В production отсутствие SMTP возвращает ошибку. На странице политики можно удалить аккаунт вместе со всеми сессиями и связанными данными. Восстановление пароля через интерфейс не реализовано.

Личный профиль после анкеты доступен без подтверждённой категории, включая провал теста: история, привязка ФСП, предпросмотр и PDF. Смена подтверждённой категории ограничена 90 днями независимо от балла; повтор того же грейда разрешён.

## Проверка

Из корня репозитория выполните:

~~~bash
npm run test:browser --prefix frontend
npm run test:assessment --prefix frontend
npm run test:resume --prefix frontend
npm run test:resume-parser --prefix frontend
node frontend/tests/auth.mjs
~~~

Браузерные сценарии запускают собственный изолированный сервис и используют отдельные тестовые аккаунты. Требуется Playwright Chromium. Все сценарии подряд: `npm run test:browser:all`.

Проверка использует Chromium из Playwright. Если браузер ещё не установлен, выполните из `frontend`: `npx playwright install chromium`.

Сценарии охватывают переход с главной в кабинеты и обратно, обязательную анкету, первую неудачную и успешную попытки теста, историю браузера, перенос запроса, поиск и сохранение подборки, фильтр ФСП, обязательную зарплату и границы диапазона, приглашение, видимость контактов после принятия, ограничения двух кабинетов, скрытие профиля, сохранение категории после неудачи, интервал смены категории, сохранение состояния, клавиатуру, контраст и мобильную вёрстку. Скриншоты записываются в `frontend/test-results/` и исключены из Git.

Проверка резюме использует синтетические PDF и DOCX, изображение с русским и английским текстом и PDF без текстового слоя. Она проверяет настоящее OCR, отмену, ошибки файлов, ручные изменения, согласия, отсутствие внешних запросов и сохранение данных. Для частной проверки своих PDF на сервере разработки задайте `PREDEL_RESUMES` с путём к папке; `PREDEL_SCAN` принимает путь к изображению. В вывод попадают только имена файлов, способ чтения и перечень найденных полей. Личные документы не являются тестовыми данными репозитория.

## Структура

- `src/App.tsx` — навигация, выбор роли, состояние и диалоги.
- `src/model.ts` — демонстрационные данные, подбор и правила доступа в интерфейсе.
- `src/assessment.ts` — запросы тестирования и восстановление попытки; ключей ответов нет.
- `src/resume.ts` и `src/resume-parser.ts` — чтение документов, OCR и предложения полей анкеты.
- `scripts/prepare-resume-assets.mjs` — подготовка локальных ресурсов библиотек и двух OCR-моделей с проверкой SHA-256; запускается при установке зависимостей и сборке. Ресурсы исключены из Git и попадают в готовый сайт при сборке.
- `../server/` — основной API Node.js, регистрация, закрытый банк, оценивание, сессии и SQLite. Каталог `../backend/` содержит дополнительный вариант FastAPI, который не запускается основными командами.
- `src/pages/` — главная страница, анкета кандидата, кабинеты, приглашения, профиль компании и тестирование.
- `src/landing.css` — стили исходной главной, ограниченные её контейнером.
- `src/components/` — логотип, примеры кабинетов, модальное окно, профиль кандидата и форма приглашения.
- `public/brand/` — оригинальный логотип ФСП и полоса логотипов, извлечённые из предоставленного PPTX.
- `public/assets/fonts/` — локальный Manrope с исходной лицензией OFL.
- `public/assets/images/` — оригинальное изображение брелоков из архива.

Дизайн главной, изображение брелоков и файл фиксации зависимостей взяты из React-части `backend.zip`. Тексты и примеры адаптированы под подбор специалистов. Презентационная студия и её API не перенесены: они относятся к другому продукту. Подробности — в [описании прототипа](../docs/interface.md).
