# Backend платформы

Основной API работает на Node.js 24 со встроенными HTTP, криптографией и SQLite. Банк и ключи ответов загружаются только сервером. Аккаунты, профили, анкеты, компания, сохранённые подборки, приглашения, вакансии и отклики хранятся на сервере; браузер использует локальную копию. Семантический поиск вызывает постоянный локальный Python-worker с дообученным RuBERT-tiny2 и mMARCO cross-encoder; совместную оценку определяет dev-калибровка. Для поиска внешние API и секретные ключи не нужны. Настоящая доставка писем регистрации требует SMTP.

## Запуск

Нужны Node.js 24 или новее и Python 3.11–3.12 для локальной модели. Из корня репозитория при уже подготовленном артефакте:

```bash
cp .env.example .env
npm ci --prefix frontend
npm run dev
```

На чистом checkout выполните последовательность из [README](../README.md#запуск): setup, обучение и локальная диагностика энкодера, подготовка reranker, QDA и политики приблизительных результатов, проверка и активация. Нужен Python 3.11–3.12; зависимости закреплены в `ml/requirements.txt`. Первая подготовка загружает открытые веса, далее обработка локальная. Активный артефакт выбирается через `server/data/semantic-model/active.json`; для композиции по умолчанию: `npm run activate:search-model -- server/data/semantic-runs/task-v2-search`. При готовой модели обучение и подготовку пропустите. Активация и worker проверяют файлы, политику, коэффициенты и отпечатки; смена версии переиндексирует каталог. Веса, диагностика и `.venv` исключены из Git. Готовые эксперименты не перезаписываются; дообучение после просмотра test требует нового контрольного корпуса. Пути задаются `SEMANTIC_PYTHON` и `SEMANTIC_MODEL`. [Архитектура и протокол](../docs/semantic_model.md).

`npm run dev` запускает Node.js API на `http://127.0.0.1:8787` и Vite на `http://127.0.0.1:5173`. Vite проксирует `/api`; `.env` загружается при запуске API. После `npm run build` команда `npm start` раздаёт готовый интерфейс и API на порту 8787. В PowerShell используйте `npm.cmd`, если выполнение `npm.ps1` запрещено.

## Хранилище и окружение

Основной API использует `server/data/assessment.sqlite`; путь меняется через `ASSESSMENT_DB`. Отдельные таблицы хранят аккаунты, ожидающие регистрации, сессии, попытки и результаты, профили и профессиональные секции, приглашения, вакансии и отклики. Версия состояния защищает от перезаписи изменений другой вкладкой; устаревший `baseRevision` получает 409. Локальные базы и письма исключены из Git.

| Переменная | Назначение |
| --- | --- |
| `HOST`, `PORT` | Адрес и порт основного API |
| `WEB_ORIGIN` | Разрешённый origin интерфейса |
| `COOKIE_SECURE` | `1` добавляет `Secure` к cookie при HTTPS |
| `ASSESSMENT_DB` | Путь к SQLite основного API |
| `SEMANTIC_PYTHON`, `SEMANTIC_MODEL` | Интерпретатор и артефакт локального worker |
| `NODE_ENV`, `APP_ENV` | Режим среды; production требует настоящую почту |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_TLS` | Адрес, порт и TLS-режим SMTP |
| `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Учётные данные и отправитель |
| `SMTP_TIMEOUT_MS` | Ограничение ожидания SMTP, по умолчанию 15 секунд |
| `AUTH_CODE_TTL_MINUTES`, `AUTH_SESSION_DAYS` | Срок действия кода и сессии |

Для SMTP на порту 587 используйте `SMTP_TLS=starttls`, на 465 — `implicit`. Без настроенного SMTP в локальной среде код сохраняется в `server/data/mail.log`, а не отправляется на внешний адрес. API сообщает `delivery: 'development'`, но не возвращает код. Этот режим не доказывает доставку email. В production регистрация возвращает ошибку до настройки почты.

## Контракт

| Метод | Путь | Поведение |
| --- | --- | --- |
| `GET` | `/api/health` | `{ "status": "ok" }` |
| `POST` | `/api/auth/register/request-code` | Сохраняет ожидающую регистрацию и отправляет шестизначный код |
| `POST` | `/api/auth/register/verify` | Подтверждает email, создаёт аккаунт и выдаёт HttpOnly-сессию |
| `POST` | `/api/auth/login` | Принимает `loginOrEmail` и пароль, выдаёт сессию |
| `GET` | `/api/auth/me` | Возвращает публичные сведения текущего аккаунта |
| `POST` | `/api/auth/logout` | Отзывает серверную сессию и очищает cookie |
| `GET` | `/api/assessment/program` | Возвращает программу без ключей ответов |
| `POST` | `/api/assessment/attempts` | Создаёт попытку и возвращает одноразовый токен |
| `GET` | `/api/assessment/attempts/{id}` | Требует `X-Attempt-Token` для восстановления попытки |
| `POST` | `/api/assessment/attempts/{id}/submit` | Проверяет `{token, answers}`; повтор идентичных ответов возвращает прежний результат |
| `GET`, `PUT`, `DELETE` | `/api/platform/state` | Читает, сохраняет с `baseRevision` или удаляет состояние владельца |
| `GET` | `/api/directory/options` | Возвращает варианты фильтров |
| `GET` | `/api/directory/search` | Принимает `q`, JSON-параметр `filters`, `offset`, `limit` до 100 |
| `GET` | `/api/directory/{id}/contacts` | Открывает контакты по правилам согласия и приглашения |
| `GET` | `/api/companies`, `/api/companies/{id}` | Каталог компаний и открытых предложений |
| `GET`, `POST` | `/api/vacancies` | Список вакансий или публикация предложения работодателем |
| `GET`, `PATCH` | `/api/vacancies/{id}` | Просмотр, редактирование или закрытие своей вакансии |
| `POST` | `/api/vacancies/{id}/applications` | Самостоятельный отклик кандидата |
| `GET` | `/api/applications` | Отклики своей роли |
| `PATCH` | `/api/applications/{id}` | Решение работодателя по своему входящему отклику |

Ошибки имеют форму `{ "error": "сообщение" }`. Интерфейс отправляет cookie через `credentials: 'same-origin'` и не читает токены из JavaScript.

`GET /api/platform/state` возвращает текущую идентичность в `X-Platform-Identity`. Для зарегистрированного аккаунта этот заголовок обязателен при `PUT` и `DELETE`: отправляйте значение последнего чтения вместе с `baseRevision` при сохранении. Если аккаунт изменился, API возвращает конфликт; старый черновик нужно очистить и заново прочитать данные текущего аккаунта. `GET /api/auth/me` без входа возвращает статус отсутствующей авторизации.

До входа публичный просмотр использует `predel_session`; после регистрации и входа действует `predel_account_session`. Обе cookie имеют `Path=/api`, `HttpOnly` и `SameSite=Strict`. В базе хранятся хеши случайных токенов, паролей, кодов и сессий. Подтверждённый аккаунт получает новый постоянный кабинет: гостевые демонстрационные данные автоматически не переносятся. Повторный вход с другого устройства связывает новую сессию с тем же аккаунтом. Выход отзывает сессию и очищает cookie. Сохранение частного состояния дополнительно связывается с текущей идентичностью и версией снимка.

Код подтверждения действует ограниченное время и блокируется после неверных попыток. Регистрация, вход и роли проверяются сервером; окончательный сквозной протокол проверок приведён в [статусе ТЗ](../docs/case_status.md). Первичное сохранение личной анкеты требует согласия. Правильные ответы не выдаются через API, а попытка дополнительно защищена токеном. Контакты раскрываются своему работодателю после принятия приглашения или самостоятельного отклика и только при действующем согласии кандидата.

## Каталог и данные тестов

Тексты очищаются от email и телефонов. Секции до 4000 символов и 12 000 символов на профиль кодируются окнами по 256 токенов с перекрытием 64; CLS-векторы окон нормируются, усредняются и снова нормируются. RuBERT выбирает до 50 профилей. Второй этап оценивает фактические рабочие секции, объединяя их собственный косинус с cross-encoder logit. Максимальная совместная оценка задаёт порядок и объяснение; тест и ФСП разрешают равенство. SQL проверяет зарплату, город, стаж, занятость, язык, категорию, портфолио и балл; `interpreted` и `effectiveFilters` показывают применённые условия. Если строгих результатов нет, dev-политика допускает до трёх ближайших выше отдельного порога: `approximate: true` и одно сообщение в `warnings`. Ошибки модели дают 503. После ожидания моделей повторно проверяются согласие, публикация, текст и версия; смена модели не позволяет записать старые векторы под новой версией. Фильтры без текста работают отдельно. Сервер готовит модель и индекс в фоне; первый запрос ждёт подготовки.

Банк тестов находится в `server/banks`, исходный каталог — в `server/directory-seed.mjs`. Основной Node.js API использует эти источники напрямую. Ограничители запросов находятся в памяти одного процесса; для нескольких экземпляров сервиса потребуется общее хранилище.

## Дополнительный FastAPI backend

`npm run dev:fastapi` и `npm run start:fastapi` запускают отдельный FastAPI/SQLAlchemy вариант после установки `backend/requirements.txt`. Его база — `backend/data/hh_platform.sqlite3` либо `DATABASE_URL`; PostgreSQL Compose относится к этому варианту. Он имеет собственный OpenAPI на `/openapi.json`, но не содержит локальный semantic worker и новые marketplace-эндпоинты. Данные и поведение основного API автоматически не переносятся. Полная инструкция и ограничения — в [docs/fastapi_migration.md](../docs/fastapi_migration.md).
