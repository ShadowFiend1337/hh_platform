# Сервер платформы

Node.js 24, встроенные HTTP, криптография и SQLite. Банк и ключи ответов загружаются только сервером. Профили, анкеты, компания, сохранённые подборки, приглашения и результаты хранятся на сервере; браузер использует локальную копию. Семантический поиск вызывает постоянный локальный Python-worker с действительно дообученным RuBERT-tiny2. Во время работы внешние API и секретные ключи не нужны.

Из корня: `npm run dev` запускает API на 8787 и Vite на 5173. После `npm run build` команда `npm start` обслуживает собранный сайт и API на http://127.0.0.1:8787. Сам сервер можно запустить отдельно: `node server/server.mjs`.

Данные платформы и попытки сохраняются в `server/data/assessment.sqlite`, папка исключена из Git. Для изменения пути используйте переменную окружения `ASSESSMENT_DB`; доступны также `PORT`, `HOST`, `WEB_ORIGIN` и `COOKIE_SECURE=1` для HTTPS за прокси. По умолчанию сервис слушает только 127.0.0.1. Частный профиль отделён от публичного документа; стек и языки лежат в связанных таблицах. SQL использует индексы категорий, зарплат, города и стажа. Вектор хранится компактным Float32 BLOB вместе с размерностью, версией модели и отпечатком текста.

Собранный сайт включает страницу `/privacy` и локальные ресурсы распознавания резюме: JavaScript-worker, WebAssembly, словари PDF и русскую/английскую OCR-модели. Сервер раздаёт их из `frontend/dist` с нужными MIME-типами; оригиналы файлов резюме на сервер не загружаются. После явного сохранения структурированные сведения профиля, включая выбранную историю работы и контакты, передаются платформе. В отдельный запрос тестирования входят только основные профессиональные поля анкеты, без контактов и дополнительных разделов.

На чистом checkout подготовьте модель: `npm run setup:search`, `npm run train:search`, `npm run evaluate:search`. Текущее обучение проверено на Python 3.12; версии зависимостей закреплены в `ml/requirements.txt`. Первый запуск загружает исходные открытые веса, дальше обработка локальная. Эксперимент сохраняется в `server/data/semantic-runs/task-v2`, активная модель выбирается через `server/data/semantic-model/active.json`. Веса и `.venv` исключены из Git. Уже оценённый эксперимент нельзя переобучать после просмотра test; при готовых весах этот этап пропускается. Для переключения готового артефакта: `npm run activate:search-model -- server/data/semantic-runs/task-v2`. Worker проверяет хеш весов и политику кодирования; новая версия обновляет индекс. Путь к Python можно задать `SEMANTIC_PYTHON`, к артефакту или реестру — `SEMANTIC_MODEL`. [Протокол обучения и фактические результаты](../docs/semantic_model.md).

## Контракт

| Метод | Путь | Поведение |
| --- | --- | --- |
| GET | `/api/assessment/program?specialization=Frontend&grade=Middle` | Темы, порог, время и примеры описаний; ключей нет |
| POST | `/api/assessment/attempts` | Анкета и необязательное `vacancyDescription`; фиксирует вариант, возвращает задания и отдельный токен |
| GET | `/api/assessment/attempts/:id` | Восстановление по cookie и заголовку `X-Attempt-Token` |
| POST | `/api/assessment/attempts/:id/submit` | `token` и массив `{questionId, optionId}`; сервер возвращает балл и агрегаты по темам |
| GET | `/api/platform/state` | Частное состояние своей сессии, версия снимка и публичные профили получателей её приглашений |
| PUT | `/api/platform/state` | `{state, baseRevision}`; валидация и атомарное сохранение, устаревшая версия даёт 409 |
| DELETE | `/api/platform/state` | Удаление профиля, компании, анкет, подборок, связанных приглашений, индекса и всех попыток текущей сессии |
| GET | `/api/directory/options` | Города, отрасли, языки и виды занятости для фильтров |
| GET | `/api/directory/search?q=...&filters=...&offset=0&limit=30` | SQL-ограничения и семантический подбор; `filters` — URL-encoded JSON, `limit` до 50; публичные контакты пустые |
| GET | `/api/directory/:id/contacts` | Собственные контакты либо контакты получателя принятого приглашения при действующем согласии |

Владелец попытки определяется случайной HttpOnly-cookie с SameSite=Strict, а не переданным клиентом ID кандидата. В базе сохраняются хеши cookie и токена. Идентификаторы вопросов и вариантов создаются заново; закрытые ID семейств, правильный ответ и весь банк API не выдаёт.

Попытка длится 30 минут. Просроченная незавершённая попытка не создаёт провал. Повторная отправка одинаковых ответов возвращает тот же результат; изменение после проверки даёт 409. Порог — 70/100, веса заданий одинаковые. Есть технические лимиты: до 20 новых попыток на владельца в час, 40 на IP в час и 180 API-запросов на IP в минуту. Платформа отдельно проверяет интервал 90 дней при смене подтверждённой категории; балл и основание берутся из успешной серверной попытки своего владельца, не из клиентского снимка. Неудачный тест сохраняет прежнее подтверждение.

Сессия браузера ещё не является зарегистрированным аккаунтом. Cookie защищает доступ между сессиями, но не подтверждает личность, email или принадлежность компании. Очистка cookie создаёт нового владельца: прежние частные данные становятся недоступны этому браузеру; это не удаление старой записи. Перед очисткой используйте удаление профиля. Восстановление доступа и перенос на другое устройство требуют регистрации. IP-лимит сохраняется.

Первичное сохранение заполненного личного профиля требует согласия; пустая анонимная запись компании или подборок допустима. Отзыв согласия скрывает профиль и закрывает доступ к контактам; частные сведения остаются до явного удаления. Новое приглашение может иметь только статус `sent`; просмотр, принятие и отказ меняет получатель. Отправленное предложение нельзя подменить, чужие приглашения недоступны. Изменение общего приглашения увеличивает версии обеих затронутых записей.

Тексты семантических документов очищаются от email и телефонных номеров; модель получает роль, стек, профессиональное описание, историю работы, достижения и образование. Текст до 12 000 символов обрабатывается окнами по 256 токенов с перекрытием 64; нормализованные CLS-векторы усредняются и повторно нормализуются. Ограничения зарплаты, города, стажа, языка, занятости, категории, портфолио и тестового балла применяет SQL. Разбор запроса сохраняет отрицания, альтернативы и обязательные группы навыков. Ответ содержит `interpreted` и `effectiveFilters`, чтобы интерфейс показывал фактически применённые условия. Косинусное сходство определяет порядок; балл и ФСП учитываются только при равенстве. Если веса отсутствуют или worker остановился, текстовый поиск возвращает 503; фильтры без текста продолжают работать. При запуске сервер готовит модель и индекс в фоне; запрос, опередивший подготовку, ждёт её завершения.

## Банк и вакансии

70 программ: 14 специализаций × Стажёр/Junior/Middle/Senior/Lead, 420 семейств и 1680 вариантов задач. Embedded/электроника имеет отдельные программы от цифровых основ и C до архитектуры устройства, временных ограничений, обновления и стратегии проверки. Доступные направления и отрасли определены общим открытым словарём `shared/catalog.ts`, грейды — `shared/grading.ts`; закрытые банки находятся в `server/banks`. Стажёр проверяет базовые механизмы, Senior — сложные технические сценарии, Lead — технические решения по ограничениям продукта, эксплуатации и выпуска. Эти программы имеют свои задания и не используют результат Middle для подтверждения другого грейда. Четыре варианта каждого семейства оставляют минимум два доступных после исключения последних двух попыток и предотвращают принудительный цикл из трёх наборов. Каждый тест проверяет три темы по двум фиксированным слотам: авторские уровни 1 и 2, бюджет 9. Теги вакансии выбирают наиболее подходящий из оставшихся вариантов; ядро и веса сохраняются.

72 описания вакансий — синтетические, покрывают все 70 программ. Разбор вакансии для выбора тестовых задач использует явные термины; нераспознанные требования не считаются покрытыми. Этот механизм отделён от нейросетевого поиска кандидатов. В клиенте показываются навыки именно выбранных задач и распознанные пробелы. Содержательное формирование не требует публикации вакансии работодателем.

Каталог содержит 146 вымышленных профилей с демонстрационными баллами и достижениями. Он предназначен для демонстрации, а не для подтверждения существования или квалификации названных людей. Обучение и отложенная оценка модели используют отдельный авторский синтетический корпус с разделением по семействам задач на train/dev/test. Каталог применяется в отдельной функциональной проверке `ml/search-regression.mjs`; её запросы не определяют веса, контрольную эпоху или порог модели. Небольшой эксперимент не доказывает коммерческую точность подбора.

Авторская сложность не является эмпирической. [Отчёт](../docs/assessment_validation.md) содержит автоматические результаты; [план](../docs/metrics_and_validation.md) и `calibrate.mjs` подготовлены для исследования на участниках. Небольшой банк не исключает запоминание и помощь извне.

При подготовке заданий использованы первичные справочники: [React useEffect](https://react.dev/reference/react/useEffect), [PostgreSQL isolation](https://www.postgresql.org/docs/current/transaction-iso.html), [Fetch](https://developer.mozilla.org/en-US/docs/Web/API/Window/fetch). Слой хранения использует [Node SQLite](https://nodejs.org/docs/latest-v24.x/api/sqlite.html).

Факты программ Junior/Middle сверены с [scikit-learn](https://scikit-learn.org/stable/common_pitfalls.html), [PyTorch autograd](https://docs.pytorch.org/docs/stable/notes/autograd.html), [Playwright](https://playwright.dev/docs/best-practices), [Android offline-first](https://developer.android.com/topic/architecture/data-layer/offline-first), [Kubernetes probes](https://kubernetes.io/docs/concepts/workloads/pods/probes/), [OWASP JWT](https://cheatsheetseries.owasp.org/cheatsheets/JSON_Web_Token_Cheat_Sheet.html), [WCAG 2.2](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [Scrum Guide](https://scrumguides.org/scrum-guide.html). Эти источники подтверждают факты заданий, не калибровку грейда. Все пять уровней остаются авторскими: независимая проверка качества заданий и исследование на кандидатах ещё не проведены.

Для добавленных уровней выполнена выборочная сверка: стабильность ссылок свойств и `memo` — [React](https://react.dev/reference/react/memo); `maxSurge` с явно исключёнными завершающимися pods — [Kubernetes Deployment](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/); проверка прав на объект для каждого действия — [OWASP API1](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/). Это подтверждает отдельные факты, а не весь банк или точность присвоения Senior/Lead.

Также выборочно сверены согласованность преобразований данных при обучении и инференсе и независимость контрольной выборки — [scikit-learn](https://scikit-learn.org/stable/common_pitfalls.html); управление фокусом при закрытии диалога — [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/); изоляция состояния тестов, наблюдаемые ожидания и диагностические traces — [Playwright](https://playwright.dev/docs/best-practices).

Для Embedded сверены I2C open-drain и подтяжки — [NXP UM10204](https://www.nxp.com/docs/en/user-guide/UM10204.pdf), различие API задачи и обработчика прерывания — [FreeRTOS task notification](https://www.freertos.org/Documentation/02-Kernel/04-API-references/05-Direct-to-task-notifications/04-xTaskNotify), [FromISR](https://freertos.org/xTaskNotifyFromISR.html), квантование АЦП — [ST AN2834](https://www.st.com/resource/en/application_note/cd00211314.pdf). Условия арифметических задач указаны непосредственно в вопросах; эти источники не подтверждают профессиональный грейд.

Проверки: `npm run test:server`, `npm run check:search-model`, `npm run test:assessment` при работающем сайте, `npm run validate:assessment` после сборки. Unit-тесты платформы проверяют CAS, собственность подтверждения, сохранение категории после неудачи, согласие, роли в приглашении, раскрытие контактов и удаление данных; реальное обучение и инференс проверяются отдельно.
