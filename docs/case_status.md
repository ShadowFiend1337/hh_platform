# Проверка каждого пункта ТЗ

Аудит выполнен 7 октября 2026 года; поиск повторно проверен 8 октября. Основание — [оригинальное ТЗ ФСП](specifications/ФСП%20спец.%20трек%20ТЗ.pdf), текущие исходники и фактические технические проверки. Основной работающий вариант — React, Node.js API, SQLite и Python-worker поиска. Дополнительный FastAPI использует отдельное хранилище и не заменяет основной сервер: его Swagger не описывает семантический поиск и marketplace Node.js.

**Основной пользовательский путь реализован, но полного соответствия ТЗ и готовой финальной сдачи пока нет.** Изоляция демо, софт-скиллы, просмотр истории, прямой PDF и реальная доставка кода email проверены. Объединение с `feature/resume-conversion` улучшает разбор резюме и справочники; совместимость формы исправлена, чтобы проекты, дополнительные сведения и расширенные навыки сохранялись. Политика силы профиля подключена к смысловому поиску; демонстрационные сведения ФСП согласованы в карточке, подробностях и PDF. Добавлены сохраняемые потребности работодателя и выбор рекомендованных категорий. Главные открытые пункты — качество поиска и тестирования, доверенные реальные сведения ФСП и материалы сдачи.

Статусы: **готово** — механика есть и подтверждается кодом или техническими проверками; **частично** — часть требования выполнена либо необходимое подтверждение отсутствует; **нет** — реализация или материал не найден. Наличие кода не доказывает профессиональную валидность грейда, пригодность для найма, юридическое соответствие или состоявшуюся сдачу. Рекомендации и необязательные функции отмечены отдельно.

## Результат объединения и нового контроля

Ветка конвертации выделяет места работы, проекты, достижения и дополнительные сведения. Проекты перенесены в существующее поле истории работы, интересы и дополнительные сведения — в «О себе»; достижения остаются отдельным текстовым разделом. Структурированные массивы существуют в результате парсера, но не становятся отдельными сущностями базы. Даты личных проектов не увеличивают стаж работы. Общий справочник ролей используется в подсказках форм, расширенные софт-скиллы доступны в компактном раскрытии. Импорт не назначает подтверждённый грейд и не даёт согласие вместо кандидата. Полнота распознавания не гарантируется: неполные поля нужно проверить вручную.

Минимальный профиль без исходных «О себе» и истории работы теперь может участвовать в смысловом подборе по заявленным роли и навыкам при достаточной строгой оценке. Основание прямо обозначено `evidenceKind: "competencies"` и должно достичь неизменного строгого порога; приблизительный допуск остаётся для победившей профессиональной секции. Образование и достижения сохраняют отдельную оценку. Явное отрицание опыта не превращается в положительное свидетельство из-за одного стека. Качество переноса этой политики на реальные минимальные профили требует отдельной проверки.

[Исторический авторский контроль](../ml/acceptance-control.mjs) 7 октября на [синтетических потребностях и профилях](../ml/acceptance-control.json) выявил ошибки NFC, WebAuthn и виртуальных часов. Веса того запуска в checkout отсутствовали. Для проверки исправлений 8 октября один раз подготовлена отдельная композиция из существующего v3 с заранее выбранными стандартными параметрами; checkpoint и калибровка выбраны только по dev. Этот артефакт явно передан и исходному серверу `f53839c`, и исправленному main. Модель, пороги, контрольные тексты, профили и эталон в парной проверке совпадали; исходники каждой версии зафиксированы отдельным manifest до inference. Оба полных запуска завершились без технической ошибки с подтверждением неизменности входов.

Историческая проверка серверных изменений на отдельной композиции v3 дала следующие результаты:

- Для физического NFC-пропуска подходящий профиль теперь первый; экранный пропуск/штрихкод с отрицанием NFC не выдаётся вместо него. Ответ помечен приблизительным с предупреждением.
- Для WebAuthn с аппаратным ключом подходящий профиль теперь первый; обычный парольный вход/OTP с отрицанием требуемого опыта не выдаётся вместо него. Ответ помечен приблизительным с предупреждением.
- Для детерминированного времени профиль виртуальных часов теперь первый как строгое совпадение.
- В этой исторической композиции осталось расхождение для индивидуального эффекта воздействия (uplift): вместо прежнего близкого отрицательного примера выдача пуста, ожидаемый подходящий профиль отсутствует. Её полный контроль имел статус `completed-with-findings` и ненулевой код `--strict`. Этот артефакт сейчас отсутствует; новый запуск доступной v2 не считается повтором или закрытием того результата.

Текущая доступная локальная композиция — `task-v2-search`. После всех доработок скриншота [исходный контроль и новый контроль переноса](search_control.md) прошли с проверкой неизменности исходников, модели, корпуса и авторской разметки. Известный подходящий профиль uplift найден первым с пометкой приблизительного совпадения. Поддержанные формулировки индивидуального причинного эффекта отделены от простого прогноза покупки/оттока и явного отрицания такого опыта. Это авторская регрессия, не независимая экспертиза, не доказательство релевантности всей выдачи и не воспроизведение недоступной исторической v3. Числовой отчёт качества не публикуется.

Ранее принятые контрольные сценарии не ухудшились. Бюджет, более строгий ручной фильтр и проверенные неподдерживаемые потребности сохранили ожидаемое поведение; прежняя функциональная регрессия прошла на обеих версиях. Даже принятый сценарий не гарантирует чистоту всей нижней выдачи: эталон проверяет правильного первого кандидата, присутствие ожидаемого профиля и отдельные ограничения.

Качество поиска подтверждено частично. Эта повторная проверка знакомых сценариев подтверждает серверные исправления на одной заново подготовленной композиции, но не является независимой экспертной оценкой, сравнением с историческими весами, профессиональной оценкой грейдов или результатом найма. Веса и пороги по просмотренному контролю не настраивались; для их последующей настройки требуется новый отдельно зафиксированный набор. Manifest и диагностика находятся в игнорируемом `server/data/acceptance-control`; в Git публикуются процедура, исходная разметка и [качественные выводы](metrics_and_validation.md#10-выполненный-контроль-полной-композиции).

## §2.1. Поиск и подбор

| Пункт | Статус | Что есть и что закрыть |
| --- | --- | --- |
| Основа — категория по опросу и тесту, а не самоописанный грейд | Готово как серверная механика | Категория берётся только из успешной серверной попытки; импорт не повышает грейд. По уточнению организаторов завершённые опубликованные анкеты доступны ниже подтверждённых кандидатов с отдельной самооценкой; фильтры грейда и рекомендации не считают их подтверждённой категорией |
| Сильнее тест и подтверждённая история ФСП — выше внутри категории | Механика готова; реальный источник ФСП отсутствует | [Политика](../server/search-ranking.mjs) подключена к текстовому поиску после неизменного допуска модели, до пагинации. Тест и ограниченный ФСП-бонус меняют порядок близких профилей одной подтверждённой категории, сохраняют другие категории и исходные оценки. [Проверки действующего сервиса](../server/tests/directory-rerank.test.mjs) охватывают неравные смысловые оценки, источник достижений, пороги и страницы; отдельно проверены encoder-only и QDA. ФСП-бонус сейчас только учебный и обозначен как демо; ручной ID не считается подтверждением |
| Соответствие потребности и краткая объяснимость | Механика готова; качество и охват частичны | Парная проверка на одинаковых весах подтверждает исправления NFC/WebAuthn/виртуальных часов; историческая v3 имела пустую выдачу uplift; текущие авторские проверки доступной v2 проходят отдельно, uplift обозначен приблизительным совпадением. Минимальные профили могут участвовать по явно обозначенным заявленным компетенциям при достаточной строгой оценке. Независимая экспертная и пользовательская оценка качества не проведена; отказ модели возвращает ошибку сервиса |
| Фильтры и уточнение без потери подборки | Готово | Запрос и фильтры сохраняются; прежняя выдача остаётся при ожидании/ошибке, сохранённая подборка восстанавливается |

| Нет предоставленных API, структуры реестра и датасета | Учтено | Собственные данные и предлагаемый контракт. Реальный API не блокирует сдачу; происхождение учебных достижений не скрывать |

## §5. Каждый материал сдачи

| Этап и пункт | Статус | Что закрыть |
| --- | --- | --- |

| Промежуточная сдача: демонстрация базового сценария | Механика есть; факт сдачи не подтверждён | Подготовить доступ/запись, проверить самостоятельный проход |
| Финальная сдача: обязательная ссылка на код | Код есть; доступ не подтверждён | Обеспечить эксперту доступ к приватному репозиторию и конкретной версии |

| Финальная сдача: документация DOC или PDF | Нет итогового файла | Markdown не закрывает формат. Собрать архитектуру, API, механику, результаты и инструкции; проверить экспорт и ссылку |

## §6. Критерии жюри и ограничения высокой оценки

Числовые прогнозы баллов не приводятся. Наибольший вес имеет новая механика подбора, следующий — тестирование, валидация и категоризация. Дополнительные экраны не заменяют доказательства по этим критериям.

### Новая механика подбора

| Что оценивают | Что готово | Что ограничивает оценку |
| --- | --- | --- |
| Оригинальность и работоспособность выхода на контакт | Выбор категоризированного кандидата, условия без вакансии, принятие/отказ и контакты по действию | Нужен живой показ обеих сторон и полезности для реальной потребности |
| Практическая применимость для двух ролей | Кабинеты и серверные состояния | Самостоятельный проход пользователями не проведён; минимальные профили могут участвовать по заявленным компетенциям при строгой оценке, качество и охват этого основания требуют отдельной проверки |
| Обоснованность ранжирования и объяснимость | Секция профиля, тест и бюджет; фильтры отделены от смысла; версия правила и происхождение достижений видны в ответе | Тест/ФСП влияют среди близких по задачам профилей одной подтверждённой категории; существенный разрыв релевантности не компенсируется бонусом. Источник ФСП сейчас учебный. Профессиональную пользу порядка ещё нужно подтвердить независимым эталоном |
| Пары «потребность/вакансия — кандидат», релевантность верхней выдачи | Текущие полный и дополнительный авторские контроли v2 проходят; историческое сравнение v3 сохранено отдельно | Историческое расхождение uplift относится к v3; текущий авторский контроль v2 описан отдельно; контроль не гарантирует релевантность всех нижних записей. Для настройки модели нужен новый независимый набор |
| Реальная потребность и сквозной пользовательский тест | Технический зарегистрированный путь и браузерные проверки | Независимый проход с двумя ролями или жюри не проведён; автоматический сценарий его не заменяет |

Оценка старого энкодера не является оценкой действующей связки RuBERT, cross-encoder и калибратора: [evaluate.py](../ml/evaluate.py) сохраняет эту границу. Для композиции выполнен [зафиксированный контроль](../ml/acceptance-control.mjs) и повторная проверка серверных изменений на одном отдельном артефакте; исправленные сценарии и остаточное расхождение перечислены выше. В обучающем коде предусмотрено разделение целых семейств данных; прямой утечки train/test не обнаружено. Новизна контрольного содержания и эталон авторские, автоматический gate проверяет буквальные совпадения. ТЗ допускает синтетические данные и эталон команды; реальные участники не единственный допустимый вариант, но помогают проверить переносимость.

### Тестирование, валидация и категоризация

| Что оценивают | Что готово | Что ограничивает оценку |
| --- | --- | --- |
| Устойчивость к распространению заданий | Закрытые ключи, варианты, исключение недавних задач, защита попытки/ответа; контроль фокуса и копирования с серверным журналом | Нет проверки после передачи готовых ответов; конечный банк можно запомнить. Браузерные ограничения обходятся, события не доказывают списывание и не снижают балл |
| Стабильность грейда при повторе | Фиксированная схема формы и правила повторного теста | Нет парных наблюдений разных форм у одних участников. [Калибровочный скрипт](../server/calibrate.mjs) обрабатывает наблюдения, но не создаёт их |
| Разделение слабых и сильных | Авторские уровни и пороги | Нет сравнения групп с известной квалификацией и анализа неразличающих заданий |
| Соответствие экспертной оценке или эталону команды | Программы и ответы размечены авторами | Не показано согласие грейда с отдельно зафиксированным эталоном; авторские метки сложности не заменяют сравнение |
| Категория по стеку, специализации и тесту | Каталог, программы, результат владельца; клиентская подделка не публикуется | Проверить профессиональную валидность, а не только структуру данных |
| Процедура и фактические результаты | [План](metrics_and_validation.md), технические результаты и ограничения | Провести эксперименты и записать реальные качественные выводы, ошибки и изменения. План и учебные категории не выдавать за результаты |

Для следующей версии подготовлен [проект открытого адаптивного тестирования](assessment_design.md): компетенции, рубрики, контекст опыта, продолжение теста и пересдачи. Это предложение; открытые ответы, оценивание LLM и адаптивные блоки пока не реализованы и содержательно не валидированы. Текущие ограничения из таблицы выше сохраняются.

### Остальные критерии

| Критерий | Что готово | Что осталось для сильного результата |
| --- | --- | --- |
| Удобство: проход без пояснений, группировка, читаемость, контраст и аккуратность | Минималистичный интерфейс, адаптивность, клавиатура и проверки доступности | Самостоятельные проходы обеих ролей; исправить препятствия в истории, ФСП и подготовке текста профиля. Избегать дублирующих подписей |
| Техническая проработка: код, скорость, архитектура, масштабирование и интеграции | API, хранение, модули, worker, защита частных операций, тесты и предметная концепция ATS | Чистый запуск, параллельная нагрузка, полный действующий API и план масштабирования. ATS OpenAPI является проектом и не закрывает описание основного Node.js API |
| Полнота и документация: обязательный путь, отсутствие ФСП, функции и документы | Основной путь, email-подтверждение с настоящим письмом, пустая история, изоляция демо, софт-скиллы, история и PDF кандидата работают | Неизменность истории, доверенный источник ФСП и итоговый комплект решения DOC/PDF. PDF кандидата не заменяет документацию решения |
| Дополнительное: вакансии/отклики, короткие задания, защита/ATS, мобильная версия | Вакансии, самостоятельные отклики и адаптивность; отдельный сервис заданий; [проработанная концепция ATS](ats_integration.md) с контрактом и примерами | Задания не подключены к API/UI; защита работодателей требует предметной архитектуры. ATS остаётся концепцией без реальной доставки и интеграционных испытаний, что допустимо по FTT.5 |
| Презентация/выступление: идея, механики, показ, обоснование и ответы жюри | Шаблон и технический материал | Нет заполненной презентации, записи/плана показа и подготовки ответов. Код не подтверждает готовность выступления |

## Очерёдность работ для максимального результата

Статусы обновляются после реализации и проверки отдельного пункта. «Выполнено» относится к указанной доработке; внешние испытания и доставку писем не заменяет наличие кода.

| Приоритет | Работа | Как принять результат |
| --- | --- | --- |
| Выполнено | Закрыть гостевой доступ к каталогам и кабинетам | Регистрация на всех входах в кабинет, серверный `401` для гостя в обоих backend, роли и отсутствие синтетической подстановки. Старые cookie не обходят вход; новые аккаунты не наследуют гостевой кеш. [Сценарии границы доступа](../server/tests/demo-isolation.test.mjs), [браузер](../frontend/tests/access-gate.mjs) |
| Выполнено как механика | Дать новому работодателю доступный каталог на чистом основном сервере | Встроенные вымышленные профили показаны после входа с меткой «Демо»; фильтры, просмотр и избранное работают, приглашения и контакты запрещены. Неизвестные записи без владельца и старая гостевая история скрыты; локальная пара изолирована. [HTTP](../server/tests/demo-catalog-access.test.mjs), [браузер](../frontend/tests/demo-catalog.mjs). Проверка с настоящим worker прошла отдельно; качество подбора и массовый импорт этим не подтверждены |
| Выполнено как механика | Софт-скиллы и история опросов/доступных тестов | Импорт, ручной выбор, сохранение, самооценка, просмотр анкет и результатов проверены. Отдельно остаётся защита исторической анкеты от замены через API |
| Выполнено как механика | Прямой PDF-экспорт | Кнопка скачивает локальный многостраничный файл с кириллицей и разрешёнными контактами. Это профиль кандидата, не комплект документации решения |
| Выполнено и проверено | Email через настоящий SMTP | Настройки и TLS/AUTH проверены, письмо получено пользователем, присланный код подтвердил аккаунт, повторный вход прошёл в отдельной тестовой базе. На другом окружении нужны его собственные настройки SMTP |
| Выполнено как механика | Подключить и проверить новую политику теста/ФСП; согласовать значки и историю | Правило работает в текстовой выдаче с encoder, cross-encoder и QDA после допуска и до пагинации. Проверены близкие неравные оценки, границы категории, отсутствие обхода порога, ручной ID без бонуса и неизменность исходных оценок. Карточка, подробности и PDF показывают одни учебные достижения с пометкой демо. Реальный доверенный источник ФСП не подключён; качество экзамена и полезность порядка этим не доказаны |
| Выполнено как механика | Сохраняемое описание потребности и рекомендованные категории по ТЗ 2.1 | Приватная сущность с командой, задачами, стеком, специализацией, грейдом и дополнительными условиями хранится в SQLite. Категории строятся по всем допущенным подтверждённым профилям, выбор показывает людей без ослабления условий. Проверены хранение, владельцы, конфликты, страницы, ошибки и доступность. Учебные профили входят в счётчики с указанием их числа; качество рекомендаций наследует ограничения поиска. [Контракт](employer_needs.md), [сервер](../server/tests/category-recommendations.test.mjs), [браузер](../frontend/tests/hiring-needs.mjs) |
| Текущая v2 проверена; независимая оценка открыта | Полный авторский контроль активной композиции | Сервер до и после исправлений проверен на одном замороженном артефакте и неизменном эталоне; исправления NFC/WebAuthn/виртуальных часов подтверждены, историческая v3 остаётся неперепроверенной; доступная v2 проходит отдельный текущий контроль. После настройки модели нужен новый набор |
| Критерий тестирования | Разные формы, переданные ответы, повторный грейд и соответствие эталону | Наблюдения собраны, есть сравнение с командной/экспертной квалификацией и разбор слабых заданий. Отчёт может быть качественным, как согласовано |
| Параллельно: сдача | Презентация, DOC/PDF, запись полного пути или доступный прототип | Эксперт открывает ссылки, видит нового кандидата, две роли, поиск, контакт и дополнительный отклик; запускает проект по инструкции |
| Параллельно: документация | Архитектура, основной API, версии/лицензии и контракт ФСП | Роли, cookie, идентичность/ревизии, попытки, запросы/ответы/ошибки; основной Node не смешан с FastAPI |
| Затем: техническое подтверждение | Новый checkout, другие браузеры и параллельный сценарий | Команды работают без текущих артефактов; ограничения ОС, ресурсов и нагрузки зафиксированы и устранены по необходимости |
| Выполнено как концепция | ATS: синхронизация вакансий, откликов и статусов | [Документ](ats_integration.md), [проект API](contracts/ats.openapi.json), примеры обмена и ошибки проверены на уровне структуры и домена. Реального подключения нет; оно не требуется для MVP по FTT.5 |
| Затем: дополнительные баллы | Концепция защиты работодателей; при наличии времени — короткие задания | Защита: состояния компании, жалобы, модератор, ограничения, приостановка. Задания: назначение, ответ и актуальность. Реальная ATS может быть дальнейшим развитием после процедур передачи ПД |

Реальный API ФСП, SMS, обязательный Keycloak, микросервисы и обязательный Docker в ТЗ не требуются. Дополнительные технологии полезны для воспроизводимости и демонстрации. Главные оставшиеся доказательства — полезность ранжирования, профессиональная состоятельность теста и самостоятельный сквозной проход; максимальный балл нельзя обещать только по наличию функций.
