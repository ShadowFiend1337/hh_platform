# Результаты соревнований из открытых публикаций

Реализовано в основном Node.js backend и React: реестр официальных страниц, разбор HTML-таблиц и новостей, очередь обновлений SQLite, общий поиск результатов и привязка через модерацию. Доступ к API Федерации и регистрация внешнего приложения для этого пути не нужны. Контракт — [OpenAPI 1.5.0](api/integrations.openapi.json).

## Пользовательский путь

Кандидат сохраняет профиль с согласием и открывает «Внешние подтверждения» → «Результаты из открытых источников». Поиск принимает имя участника или команду, позволяет выбрать источник и листать результаты. Показываются факты, ссылка на оригинал и короткий фрагмент публикации. Для PDF остаётся ссылка на конкретную страницу.

Кнопка «Это мой результат» открывает существующую заявку: описание участия, до пяти HTTPS-ссылок и/или PDF/PNG/JPEG до 2 МБ. До одобрения запись не становится подтверждением профиля. Материалы доступны владельцу и модератору; работодателю они не передаются.

Модератор проверяет опубликованный результат и принадлежность кандидату. **Для команды обязательна отдельная проверка участия в составе на этом соревновании**, `teamMembershipConfirmed=true`. Место команды не доказывает личный вклад. Несколько подтверждённых участников могут связать один командный результат с разными профилями. Индивидуальная запись может иметь только одного одобренного владельца; ограничение защищено индексом БД. Совпадение ФИО не подтверждает личность автоматически.

Публикация одобренного достижения зависит от согласия, видимости профиля и подтверждённой профессиональной категории. Новые записи имеют `provider=public-achievements`, `verificationMethod=manual_review`; алгоритмические командные результаты получают scope `team_result`. Они не меняют профессиональный грейд и не включают существующий признак/бонус ФСП. Старый подтверждённый индивидуальный PDF ФСП сохраняет прежнее поведение.

## Сбор и свежесть

В `/moderation` появился блок «Сбор из открытых источников»: состояние страницы, число записей, дата последнего успешного разбора, ошибка и кнопка обновления. Обновление создаёт задачу в SQLite; активные задачи не дублируются, незавершённая работа восстанавливается после перезапуска.

При `PUBLIC_SOURCE_AUTOSYNC=1` (по умолчанию) worker раз в минуту проверяет расписание. Зарегистрированные HTML-страницы обновляются раз в сутки; после ошибки повторная попытка — через час. Между страницами выдерживается 1,1 секунды. Если текущий процесс завершён, worker не работает. Очередь рассчитана на **один экземпляр основного Node.js backend**, как существующая очередь интеграций.

Снимок публикуется целиком после проверки структуры, названия/контекста события, числа строк и уникальности результатов. При ошибке остаются последние успешно извлечённые факты, но источник помечается недоступным для подтверждения. Неполная или неожиданно изменённая страница не публикуется частично. Задачи содержат безопасные коды ошибок, без исходного HTML. Завершённая операционная история очищается через 30 дней; аудит модерации хранится отдельно.

Для HTML сохраняются два хеша: исходной страницы и извлечённых результатов. Подтверждение сравнивается со снимком **конкретного результата**: реклама и меню не снимают его; исправление места/имени/результата снимает. При удалении записи, недоступности страницы или отсутствии успешного обновления более семи суток подтверждение неактивно. При восстановлении источника тот же результат может снова стать активным в пределах 90-дневного срока проверки принадлежности. Исправленный результат требует отзыва и повторной подачи с новым снимком; он не переписывает одобренную заявку незаметно.

Изменение определения источника в реестре тоже требует нового разбора: старый совместимый только с прежней конфигурацией снимок не используется для одобрения. Во время сетевой проверки одобрение блокируется. Кнопка «Проверить свежесть источника» выполняет синхронный разбор HTML либо существующую проверку хеша PDF. Автоматический HTML-worker не запускает OCR новых PDF.

## API

| Маршрут | Доступ / результат |
| --- | --- |
| `GET /api/integrations/public-achievements/search?name=Гутид&limit=10&offset=0` | Кандидат с согласием; необязательный `sourceId`; всегда `identityVerified=false` у найденной публикации |
| `GET /api/integrations/public-achievements/sources` | Кандидат с согласием; зарегистрированные HTML-источники и состояние сбора |
| `GET /api/moderation/sources` | Назначенный сервером модератор; состояние источников и активные задачи |
| `POST /api/moderation/sources/{sourceId}/collect`, тело `{}` | Модератор; `202 {job}`; до 10 запросов/10 минут |
| `GET /api/moderation/sources/jobs/{jobId}` | Модератор; `queued/running/succeeded/failed` |
| `POST /api/moderation/sources/{sourceId}/check`, тело `{}` | Модератор; непосредственная проверка; до 5 запросов/10 минут |

Заявки используют прежние маршруты `/api/achievement-claims` и `/api/moderation/claims`; поле `record` теперь допускает PDF или HTML-запись. Пишущие запросы требуют `X-Platform-Identity=auth:<account.id>`. Роль работодателя сама по себе не даёт прав модератора. Назначение прав и настройка ключа шифрования описаны в [модерации](achievement-moderation.md). Старый `/api/integrations/fsp-public/search` сохраняет прежний строгий поиск по ФИО и PDF-контракт.

## Добавление источников

Реестр: `server/integrations/data/public-achievement-sources.json`. Для каждой страницы задаются официальный издатель, URL, тип, адаптер, ключ соревнования, название/дата/дисциплина, индивидуальное или командное участие, ожидаемое число результатов и обязательные маркеры текста. Метаданные события проверяются оператором по официальной публикации. `eventKey` и ключ участника/команды задают стабильный ID; повторные публикации одного события требуют одинакового ключа события. Структурированные таблицы имеют приоритет над новостями при совпадении ID.

HTML разбирается через parse5 без исполнения JavaScript. Сеть ограничена HTTPS-хостами и путями адаптеров, таймаутом 10 секунд, размером 1 МБ и запретом редиректов. Пользовательский URL нельзя передать в импорт или задачу. Новый сайт требует изменения списка доверенных адресов, адаптера и проверок; универсального парсера произвольной новости здесь нет.

```sh
npm ci
npm run import:public-achievements -- --discover
npm run import:public-achievements -- --source fsp-robotics-cup-2026-news --output /tmp/public-results.json
npm run import:public-achievements -- --source icpc-world-finals-2025 --output /tmp/public-results.json
```

`--discover` читает официальный список новостей ФСП и выводит подходящие ссылки для выбора оператором. Он **не регистрирует страницы и не публикует достижения автоматически**. После выбора нового события нужно проверить метаданные и формат, добавить его в реестр и перезапустить сервер. Мониторятся только зарегистрированные страницы; автономного обхода всего интернета нет.

Без `--output` импортёр обновляет `server/integrations/data/public-achievements.json` — начальные снимки для новых БД. Существующая БД не заменяется этим файлом: для неё используйте кнопку обновления или API сборщика. `--cached-dir PATH` позволяет разбирать локальные HTML-файлы с именем `<sourceId>.html`. При сбое CLI сохраняет предыдущий успешный снимок и завершает команду с кодом 1. CLI не подтверждает принадлежность и не изменяет профили пользователей.

Начальные снимки — реальные факты из официальных страниц, не вымышленные достижения. Свежесть оценивается по времени успешного разбора; старые начальные данные нужно обновить перед одобрением. Парсер ИТМО проверен на контролируемой структуре, но требует успешной загрузки и проверки настоящего HTML до использования результатов.

## Проверка реализации

```sh
npm run test:server
npm run build
npm run test:public-achievements-browser
npm run test:moderation-browser
npm run test:integrations-browser
```

Добавлены 16 серверных проверок: адаптеры и защита от неполного/чужого события, запрет недоверенных URL, неизменность хеша при правках оформления, очередь/перезапуск/остановка во время I/O, сохранение прошлого снимка, свежесть/повторы, инвалидирование при смене конфигурации, CLI, права API, проверка состава, несколько участников команды, единственный владелец индивидуального результата и приватность. Браузерный сценарий проходит поиск новости → материалы → сбор → обязательная проверка состава → одобрение → публикация → исправление места → отзыв. На 8 октября 2026 прошли 355 серверных тестов, сборка и пять браузерных сценариев интеграций; OpenAPI и 12 реальных ответов методов сервиса проверены по схемам. CLI также успешно загрузил настоящую новость ФСП; таблица ICPC успешно загружена и разобрана тем же CLI.
