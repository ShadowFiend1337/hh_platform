# Прокторинг и защита от списывания

Обновлено 9 октября 2026 года. Организаторы (FTT.4) называют проверку списывания «большим плюсом»; в решении она реализована на двух уровнях: серверном (его нельзя обойти из браузера) и браузерном (сдерживает и фиксирует нарушения).

## Серверный уровень

| Мера | Как работает |
| --- | --- |
| Последовательная выдача | Сервер отдаёт только отвеченные вопросы и текущий. Весь тест нельзя сфотографировать или переслать целиком. |
| Фиксация ответа | `POST /api/assessment/attempts/{id}/answer` закрепляет ответ на текущий вопрос; изменить его или ответить «вперёд» нельзя (`409`). |
| Лимит времени на вопрос | 120 секунд от момента показа (по серверным часам) плюс 8 секунд на сеть. Поздний ответ сохраняется, но засчитывается как неверный. Это главный барьер против поиска ответа во внешней LLM. |
| Ключи только на сервере | Правильные ответы, идентификаторы семейств и вариантов не попадают в браузер. Варианты перемешиваются, идентификаторы непрозрачны. |
| Аннулирование | Третий уход со страницы теста аннулирует попытку на сервере: результат `annulled: true`, `passed: false`, балл 0. Грейд не подтверждается, повтор того же грейда — через срок пересдачи. |
| Уникальность набора | Каждый кандидат получает свою выборку из банка с учётом экспозиции, ранее показанные ему задания исключаются (см. [dynamic_bank.md](dynamic_bank.md)). |

## Браузерный уровень

- Перед стартом кандидат видит правила и подтверждает их галочкой; без этого тест не начинается.
- Тест открывается в полноэкранном режиме, навигация кабинета, выход и история браузера заблокированы до завершения.
- **Нарушение (уход)** — потеря фокуса окна, скрытие вкладки, выход из полноэкранного режима. Вопрос и варианты удаляются из DOM, кандидат видит «Вы покинули тест · Нарушение N из 3». Возврат — кнопкой «Вернуться к тесту» (снова включает полноэкранный режим). Время на вопрос продолжает идти.
- **Сигналы** (не нарушения, но журналируются): копирование, вырезание, вставка, контекстное меню, перетаскивание, Ctrl/Cmd + C/X/V/A/P/S/U/F, F12 и Ctrl+Shift+I/J/C/K, клавиша PrintScreen (вопрос на 1,5 с скрывается), печать (CSS `@media print` прячет тест).
- Водяной знак с логином и кодом попытки на области вопроса: утёкший снимок экрана указывает на источник.
- В черновике кода работает набор текста, отступы, отмена; буфер обмена отключён и там.

## Журнал событий

`POST /api/assessment/attempts/{id}/integrity`:

```json
{ "token": "токен попытки", "event": { "id": "UUID события", "kind": "fullscreen_exit" } }
```

Нарушения: `focus_lost`, `visibility_hidden`, `fullscreen_exit`, `second_tab`. Сигналы: `copy_blocked`, `paste_blocked`, `shortcut_blocked`, `screenshot_key`. Время задаёт сервер; повтор того же события идемпотентен; на попытку хранится не более 128 событий. Ответ содержит сводку `departures`, `blockedCopies`, `blockedActions`, `fullscreenExits`, а также `remaining` и `annulled` (при аннулировании — итоговый `result`). Сводка без времени событий сохраняется в результате попытки и видна кандидату в истории.

## Ограничения

Браузерные ограничения можно обойти (вторым устройством, отключением скриптов). Поэтому решающими остаются серверные меры: последовательная выдача, лимит времени на вопрос, уникальный набор и пилотная калибровка заданий. Камера и запись экрана не используются: это избыточная обработка персональных данных для MVP (152-ФЗ).

## Проверки

- `node --test server/tests/assessment-integrity.test.mjs` — владение, токен, идемпотентность, лимит событий, аннулирование после трёх уходов, последовательная выдача, поздние ответы.
- `npm run test:assessment-guard` — браузер: правила, блокировка буфера и горячих клавиш, предупреждения, перезагрузка, полный проход и аннулирование, автоматическая проверка доступности.
- `node frontend/tests/code-editor.mjs` — черновик кода внутри последовательного теста, повтор отправки после сбоя.
