# Проверка механики тестирования

Дата: 2026-10-05. Версия банка: 2026.10.1. Команда воспроизведения: `npm run build && npm run validate:assessment`.

Это результаты автоматической проверки структуры и поведения. Они не являются исследованием на кандидатах, измерением фактической сложности или доказательством профессионального грейда.

## Варианты

Размер банка: 96. В каждой попытке — три темы, по одному базовому и прикладному заданию каждой темы; одинаковые веса, сумма авторских уровней сложности 9. Для каждой программы сгенерированы 200 попыток. У каждой проверены число заданий, темы, уровни и исключение задач последних двух попыток. Проверка разнообразия дополнительно отсекает короткий предсказуемый цикл наборов.

| Программа | Задач в банке | Наборов до перестановок | Проверено попыток | Различных наборов в прогоне | Бюджет |
| --- | --- | --- | --- | --- | --- |
| Frontend Junior | 24 | 4096 | 200 | 194 | 9 |
| Frontend Middle | 24 | 4096 | 200 | 195 | 9 |
| Backend Junior | 24 | 4096 | 200 | 194 | 9 |
| Backend Middle | 24 | 4096 | 200 | 190 | 9 |

Разные наборы не означают равной фактической сложности. Метки 1 и 2 назначены авторами; необходимы независимая экспертиза и парные прохождения. Малый тест имеет дискретные результаты: 4/6 = 67/100, 5/6 = 83/100; порог 70 требует минимум пяти верных ответов.

## Формирование из вакансий

Все шесть описаний синтетические. Ниже — один фактически собранный вариант на каждое описание. Распознанные требования влияют на выбор содержательной задачи внутри фиксированного слота; ядро, веса и грейд сохраняются. Показаны навыки выбранных задач, а не всего банка. Неизвестные словарю требования не считаются автоматически покрытыми.

| Описание | Проверяемые совпадения | Распознано, но не проверяется этим вариантом |
| --- | --- | --- |
| Frontend Junior | HTML, CSS, JavaScript, Доступность, Формы HTML, Flexbox, Адаптивная вёрстка, События DOM | Нет распознанных пробелов |
| React разработчик | JavaScript, React, Доступность, HTTP, Производительность, Состояние React, Эффекты React | Тестирование |
| Frontend продуктовой команды | JavaScript, React, HTTP, Безопасность, Производительность, Promise, Асинхронные ошибки | TypeScript, Vue, Тестирование |
| Backend Junior | HTTP, REST, SQL, Транзакции, Безопасность, SQL JOIN, Пароли, Права доступа | PostgreSQL, OWASP |
| Backend платёжного сервиса | SQL, PostgreSQL, Транзакции, Идемпотентность, Outbox, Повторные запросы, Наблюдаемость, Трассировка | Нет распознанных пробелов |
| Backend сервиса заказов | REST, SQL, PostgreSQL, Транзакции, Очереди, Повторные запросы, Circuit breaker, Dead-letter queue | Docker, Kubernetes, Наблюдаемость |

Автотест отдельно проверяет выбор разных задач для вакансий с доступностью и XSS, а также трассировкой и dead-letter queue. Повторение одной вакансии не отменяет исключение последних двух вариантов.

## Скрытые ответы

Собранные JavaScript-файлы браузера проверены: в них нет текста вопросов банка, идентификаторов семейств и закрытого поля correctOptionId. Ключи хранятся только на сервере. Вопросы и варианты ответов конкретной попытки доступны кандидату; верные ответы API не возвращает. Правила HTTP, повторная отправка, истечение времени, лимиты и восстановление базы проверяются `npm run test:server`; пользовательский путь, перезагрузка и ошибка сервиса — `npm run test:browser` и `npm run test:assessment`.

## Что пока не доказано

Нет данных реальных парных прохождений, независимых оценщиков и внешней помощи. Не измерены V-TEST-01–V-TEST-03 и устойчивость к запоминанию всего банка. Небольшой банк каждой программы можно выучить; непрозрачные ID, варианты и лимиты снижают повторное использование готового ответа, но не исключают передачу содержания. Для следующего исследования подготовлен `server/calibrate.mjs`; процедура описана в [плане валидации](metrics_and_validation.md).
