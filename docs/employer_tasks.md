# Регулярные задания от работодателя

Обновлено 10 октября 2026 года. Дополнительный функционал к ТЗ: короткие практические задания поддерживают «свежесть» профиля, не подменяя тест. Подтверждённый грейд меняет только серверный тест.

## Как работает

1. Работодатель назначает задание кандидату, с которым уже есть связь: **отклик** на вакансию компании или **принятое приглашение**. Остальным кандидатам задание недоступно.
2. Кандидат видит задание в разделе «Приглашения → Задания» и отправляет ответ до срока (от 15 минут до 90 дней; по умолчанию 7 дней).
3. Работодатель проверяет ответ: «Принять», «На доработку» или отменяет задание. Комментарий виден кандидату.
4. Задание можно сделать регулярным: каждую неделю, месяц или квартал. Следующий цикл открывается автоматически после принятия ответа с тем же сроком на ответ.
5. Последнее принятое задание отмечается в подборке работодателя: «Задание сегодня / вчера / N дн. назад».

## ИИ-разбор ответа

Кнопка «ИИ-разбор» на присланном ответе даёт работодателю подсказку: рекомендация (принять или доработать), оценка 0–100, сильные стороны, пробелы и уточняющие вопросы.

- Модель: открытая Qwen через OpenRouter (`server/task-review.mjs`), как у ИИ-помощника ([LLM](llm_usage.md)).
- В модель уходят только название, условие и текст ответа. Имя, контакты и идентификаторы не передаются. Ответ кандидата помечен как данные: инструкции внутри него модель игнорирует.
- Без ключа или при сбое модели выполняется проверка полноты по ключевым словам условия, длине и наличию конкретики; в интерфейсе указан источник разбора.
- Решение всегда принимает работодатель. Лимит — 20 разборов за 10 минут на аккаунт.

## API

| Метод | Путь | Роль |
| --- | --- | --- |
| `GET` | `/api/tasks` | обе роли: свои задания; у кандидата ещё `freshness` |
| `GET` | `/api/tasks/candidates` | работодатель: кому можно назначить задание |
| `POST` | `/api/tasks` | работодатель: `{ candidateId, title, description, dueAt, recurrenceDays: 0 \| 7 \| 30 \| 90 }` |
| `POST` | `/api/tasks/{id}/answer` | кандидат: `{ answer }` |
| `POST` | `/api/tasks/{id}/review` | работодатель: `{ status: approved \| rejected \| cancelled, feedback }` |
| `POST` | `/api/tasks/{id}/ai-review` | работодатель: подсказка по присланному ответу |

Тестовые аккаунты разделены с реальными: задания между ними невозможны даже при подложенной связи.

## Тестовые кабинеты

`local_employer` и `local_candidate` (пароль на странице входа) начинают с полным циклом: одно задание принято, одно ждёт проверки (можно запустить ИИ-разбор), одно ждёт ответа кандидата.

## Проверки

- `node --test server/tests/refresh-tasks.test.mjs server/tests/tasks-http.test.mjs` — права ролей, сроки, повторы, удаление, изоляция, ИИ-разбор без персональных данных и с откатом к проверке по ключевым словам.
- `npm run test:tasks` — браузер: разбор, принятие со следующим циклом, новое задание по шаблону, ответ кандидата.
