# Банк открытых задач

Собран отдельный авторский серверный корпус для всех специализаций из каталога и уровней от стажёра до Lead. Он предназначен для подготовки открытого экзамена из [проекта](assessment_design.md). **Банк имеет статус `author-draft`: независимая предметная экспертиза и калибровка ещё не проведены, подтверждение грейда по нему отключено.** Действующий тест с вариантами ответа продолжает использовать прежний банк.

## Что находится в записи

Семейство содержит исходную задачу с условиями, основную группу компетенций, формат ответа, язык кода или псевдокода, предметный разбор, допустимые альтернативы, критические ошибки и рубрику. У каждого грейда заданы дополнительные условия и ожидаемое действие. Отдельный критерий глубины учитывает именно это действие; смена названия уровня сама по себе не меняет оценку.

Уровни одной задачи относятся к одному семейству и не считаются независимыми вопросами. Перефразировка, название компании или другая фамилия также не создают новую задачу. Проверка точных дублей выполняется автоматически; смысловую независимость и применимость рубрик к каждому уровню ещё нужно проверить содержательно.

Компетенции соответствуют [матрице проекта](assessment_design.md). В каждом направлении есть задачи всех групп: рабочие случаи, диагностика, обоснование решения и проверка. Для технических ролей добавлены задания с кодом и псевдокодом. UXUI, бизнес-анализ и управление продуктом проверяются предметными разборами и решениями, обязательные алгоритмы им не назначаются.

## Источники и происхождение

В реестре каждого источника сохранены издатель, URL, дата обращения, назначение и способ проверки. `opened` означает успешное открытие страницы; `search-index` обозначает проверку по поисковому индексу и не выдаётся за прочтение всей страницы.

Используются первичные технические документы и публичные материалы компаний. Например, [хендбук Яндекса](https://contest.yandex.ru/tracks/algorithms/introduction/intro), [разбор процессов QA в Ozon Tech](https://habr.com/ru/companies/ozontech/articles/707092/) и [материал RWB о распределённых рейтлимитах](https://habr.com/ru/companies/rwb/articles/932050/). Техническая публикация компании является источником фактов, а не доказательством происхождения задачи из её собеседования.

Условия, ответы и рубрики написаны как самостоятельные сценарии; полные тексты чужих статей не копируются. Источники не объявляются общедоступными по разрешительной лицензии автоматически. Не заявляется, что собраны все реальные вопросы Яндекса, Ozon, WB или всех компаний и вакансий: в этой работе такой полный банк не подтверждён.

## Файлы и использование

- [Серверный модуль](../server/open-bank.mjs) объединяет корпус, закрепляет версии и формирует программы.
- [Инженерные направления](../server/open-bank/engineering.mjs): Frontend, Backend, Fullstack, Mobile, Embedded.
- [Данные](../server/open-bank/data.mjs): ML, аналитика и инженерия данных.
- [Эксплуатация и продукт](../server/open-bank/operations-product.mjs): DevOps, QA, Security, UXUI, бизнес-анализ и управление продуктом.
- [Схема](../server/open-bank/schema.mjs) проверяет структуру, происхождение, покрытие и ограничения персонализации.
- Реестры источников находятся рядом с соответствующими модулями в файлах `sources-*.json`.

Проверка корпуса и технической механики:

```powershell
npm run test:open-bank
npm run validate:open-bank
```

Сохранение закрытого примера программы для просмотра разработчиком:

```powershell
npm run sample:open-bank -- ML Middle
```

Полный экспорт для последующей серверной загрузки или работы с моделью:

```powershell
npm run export:open-bank
```

Артефакты записываются в игнорируемый каталог `server/data/open-bank/`. Они содержат эталоны и рубрики, поэтому их нельзя переносить в `frontend/public`, отдавать кандидату или публиковать вместе с клиентскими файлами. Пример является авторским просмотром, не попыткой кандидата, не присваивает категорию и не создаёт запись в истории тестирования.

Авторский просмотр подбирает задачи по группам компетенций. Он пока не закрепляет состав форматов, предусмотренный проектом экзамена: число заданий с кодом в примере может меняться. Правило отбора практических задач вместе с оцениванием ещё нужно подключить в экзаменационном движке.

Проверка структуры подтверждает наличие полей, источников, различающихся условий уровней, покрытие и возможность составить разные формы без повторения семейств. Она не доказывает правильность каждой рубрики, равную реальную сложность, устойчивость к заучиванию или профессиональный грейд.

Расширенный конечный банк также можно выучить или передать. Открытая форма и объём сами по себе не доказывают защиту; содержательные проверки с известными исходными вопросами, новые условия внутри проверенных семейств и контроль повторного раскрытия ещё нужны.

## Что остаётся до рабочего открытого экзамена

Нужно проверить решения и альтернативы по предметным областям, убедиться, что обязательные критерии применимы к конкретному заданию каждого грейда, и разобрать близкие семейства. Далее — подготовить отдельные эталонные ответы кандидатов, проверить согласованность оценивания и сопоставимость банковского и персонализированного пути.

Рубрики сейчас относятся к отдельным семействам (`criterionScope: family-local`). Для накопления свидетельств по адаптивной политике ещё нужно сопоставить их с обязательными критериями программы. Совпадение локального имени критерия у разных задач не доказывает, что они проверяют один навык; простое усреднение этих оценок не вводится.

Банк ещё не подключён к пользовательскому экзамену. Серверное сохранение открытых ответов, генерация ограниченных вариантов моделью, оценщик, политика повторных попыток и адаптивное продолжение остаются отдельными шагами. Обработчик текущего теста не принимает код как оцениваемый ответ; редактор пока сохраняет локальный черновик.

Отбор в авторском просмотре использует только непоказанные семейства и завершается явной ошибкой при их нехватке. Он не заменяет адаптивную политику. Для продолжения по одной недостаточно покрытой группе может потребоваться расширение её пула; повтор той же задачи нельзя считать новым независимым свидетельством.

Персонализация ограничена разрешёнными полями. Числа, порядок событий, сложность, ограничения ресурсов, ожидаемые действия и рубрика закреплены. Заявленный опыт и известное название компании не добавляют баллы и не подтверждают подлинность достижений; эта проверка остаётся отдельной задачей команды.
