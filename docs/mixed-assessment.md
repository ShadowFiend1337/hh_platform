# Смешанный тест и ручная проверка

Основной Node.js API по умолчанию формирует **15 закрытых вопросов и 5 открытых задач** по специализации, грейду и навыкам анкеты. Старый банк и старые попытки сохранены. `assessmentMode: 'legacy'` — явный параметр фабрики для проверки совместимости старых попыток, не переключатель интерфейса. Дополнительный FastAPI этот сценарий пока не поддерживает.

## Подготовка и решение

1. `POST /api/assessment/attempts` с `{survey, vacancyDescription?}` возвращает `202`, `id`, секретный `token`, `status: preparing`, счётчик `generation.done/total`. Перед генерацией проверяются доступ, лимиты, пересдача и наличие незавершённого теста. Без `OPENROUTER_API_KEY` возвращается `503`; старые вопросы автоматически не подставляются.
2. Генератор делает **13 запросов на полный тест**, каждый создаёт один новый кейс: восемь закрытых кейсов с двумя вопросами и пять открытых. Из последнего закрытого кейса в тест включается один вопрос — всего 15. Полный вариант с обоими вопросами сохраняется отдельно. При небольшом пуле компетенций исходные кейсы повторяются, но новые варианты проходят проверку повторов; уникальность всех 20 компетенций не заявляется. Выборка старается покрыть разные компетенции, учитывать стек и избегать недавно предъявленных исходных кейсов.
3. В памяти процесса работают максимум два запроса одновременно и четыре задания подготовки тестов. Промежуточный счётчик и снимок хранятся в SQLite. Автоматических повторных платных запросов нет. Ошибка любого кейса переводит тест в `failed`, без результата и запрета пересдачи. После перезапуска незавершённая подготовка помечается `failed`, а не оплачивается повторно. Готовые тесты и начатые попытки переживают перезапуск. Лимиты процесса не предназначены для запуска нескольких экземпляров над одной базой.
4. `GET /api/assessment/attempts/:id` требует сессию владельца и `X-Attempt-Token`. До начала возвращаются метаданные и счётчик, без заданий. Подготовка ограничена 20 минутами, ожидание начала готового теста — 30 минутами.
5. `POST /api/assessment/attempts/:id/start` с `{token}` запускает готовый тест. **Время решения не расходуется на генерацию.** На закрытый вопрос отведены 3/4/5/6/7 минут для Intern/Junior/Middle/Senior/Lead. На открытый — время исходного кейса, обычно 10–40 минут. Общий срок — сумма лимитов выбранных заданий плюс 10 минут на отправку. Эти лимиты предварительные, время решения на реальных участниках не измерено.
6. `POST /api/assessment/attempts/:id/answer` принимает `{token, questionId, optionId}` для закрытого или `{token, questionId, answerText}` для открытого. `null` означает пропуск. Текст до 12 000 символов, включая SQL/код и объяснение. Текущий вопрос показывается последовательно; ответы неизменяемы, следующие вопросы заранее получить нельзя. Просроченный ответ сохраняется с `late`, получает ноль. Черновики текста и кода восстанавливаются в той же вкладке; код открытого ответа входит в отправленный текст.
7. `POST /api/assessment/attempts/:id/submit` с `{token}` допускается только после фиксации всех 20 ответов. Отправка массива ответов для нового формата запрещена. Закрытая часть оценивается автоматически. В одной транзакции сохраняется результат `pending-review` и запись очереди `assessment_reviews`. Повторная отправка возвращает тот же результат.

Контроль вкладки и полноэкранного режима включается только после начала решения. Сохраняется существующее аннулирование после третьего ухода. Черновик подготовки не считается активной попыткой для ассистента. Кандидат не получает ключи, эталон, рубрику, исходный паспорт и обоснование LLM.

## API модератора

Нужны действующая сессия и назначенное сервером `canModerate`; право проверяется при каждом запросе. Учебные локальные аккаунты и обычные аккаунты изолированы по существующим правилам проекта. Собственный тест оценивать нельзя.

| Запрос | Результат |
| --- | --- |
| `GET /api/moderation/assessments?status=pending&limit=20&offset=0` | Очередь, количество, версия, кандидат, грейд, число верных закрытых ответов. Также доступны `completed` и `invalidated`; лимит 1–100. |
| `GET /api/moderation/assessments/:id` | Все 20 заданий, зафиксированные ответы и опоздания, ключи, эталоны, рубрики, полные варианты, паспорта исходных кейсов, ссылки и обоснование сложности. |
| `POST /api/moderation/assessments/:id/decision` | Ручное решение с проверкой версии; требуется `X-Platform-Identity: auth:<account-id>`. |
| `GET /api/assessment/results/:id` | Собственный результат кандидата без ключей и внутренних материалов. Позволяет обновлять статус после отправки без хранения токена попытки. |

В кабинете `/moderation` добавлена вкладка **«Тесты»**. Для оценки обязательны все пять открытых ответов, все критерии каждого ответа и проверки `solutionCorrect`, `sameReasoning`, `gradeAppropriate`, `similarWorkload`, `unambiguous`. Отметки качества относятся ко всем выданным заданиям, включая закрытые. Оценка критерия — 0, 1 или 2 по доверенной шкале. У пропущенного/просроченного ответа все критерии могут быть только нулевыми. Комментарии к ответам и итоговый комментарий возвращаются кандидату.

Тело решения:

```json
{
  "version": 1,
  "decision": "grade",
  "note": "Комментарий кандидату",
  "contentChecks": {
    "solutionCorrect": true,
    "sameReasoning": true,
    "gradeAppropriate": true,
    "similarWorkload": true,
    "unambiguous": true
  },
  "marks": [
    {
      "questionId": "идентификатор открытой задачи",
      "criteria": [{"criterionId": "идентификатор критерия", "score": 1}],
      "comment": "Комментарий к ответу"
    }
  ]
}
```

Пример сокращён: реально нужны ровно пять элементов `marks` и все критерии из детали. Итоговый `score`, правильность закрытых вопросов и вес частей клиент передать не может. Конкурирующее/повторное решение получает `409`; версия, автор, время, проверки и оценки сохраняются. Удаление аккаунта кандидата каскадно удаляет его очередь и ответы.

Успешная проверка в той же транзакции подтверждает профиль и обновляет публикацию, даже если кандидат ушёл со страницы теста. Сервер сохраняет ограничение смены категории в 90 дней и исключение для уверенного результата; проверка старой анкеты не подменяет новую выбранную категорию. Исторический результат в любом случае доступен кандидату. Провал сохраняет уже подтверждённый грейд.

При дефекте условий модератор отправляет `{version, decision: "invalidate", note: "Причина длиной от 10 символов"}`. Результат становится `invalidated`, не подтверждает грейд и не вводит ожидание пересдачи. Проверенный результат `completed` следует прежней политике успешного теста/пересдачи; дата итогового результата и начало ожидания пересдачи — момент решения модератора, время отправки сохранено в очереди отдельно. `pending-review` не показывается как провал и не подтверждает категорию.

## Оценка и пределы достоверности

Закрытая часть: `100 × верные / 15`. Открытая задача: `100 × сумма баллов критериев / (2 × число критериев)`. Открытая часть — среднее пяти задач. Итог — округление `0.5 × закрытая часть + 0.5 × открытая часть`. **Порог 70**, уверенный результат 90. Все верные закрытые и все нулевые открытые дают 50; все верные закрытые и половина баллов открытых — 75. Используются неокруглённые баллы частей, чтобы не менять порог из-за промежуточного округления.

Обоснование сложности получает **модератор**, вместе с исходным паспортом и новым эталоном. Это материал для независимой предметной проверки, а не доказательство модели самой себе. Рубрика нового кейса сохраняет критерии исходного; исходные шкалы и грейд берутся с сервера. Структурная проверка генератора не гарантирует правильность решения или равенство сложности. Ссылки корпуса — материалы для авторских кейсов, не точная атрибуция дословных упражнений; эта оговорка показана модератору.

Пользователь разрешил выдавать новые варианты в тест и проверять их после решения. Поэтому попытка содержит снимок варианта с `unverified-variant`; отдельный авторский реестр остаётся с `active=0`, а процедура предварительного пилота не превращается автоматически в аттестацию. Ручная проверка одной попытки также не меняет глобальный статус варианта и не выдаёт статистическую калибровку всему банку. [Генератор и независимый пилот](review-bank/generation.md) сохраняются как отдельные процедуры. Для устойчивого подтверждения сопоставимости нужны экспертная проверка исходных грейдов, пилот и анализ результатов реальных кандидатов.

## Проверка реализации

`npm run test:mixed-assessment`, `npm run test:mixed-assessment-browser`, `npm run test:server`, `npm run build`. Новые тесты проверяют схемы всех 14 специализаций × 5 грейдов, последовательность, неизменяемость/размер открытых ответов, доступ, ручную оценку 50/50, отзыв, пересдачу, восстановление текста/кода и обновление профиля. Используются явно помеченные синтетические транспортные фикстуры. Они не проверяют качество живой LLM или сложность задач. В текущем окружении нет настроенного ключа OpenRouter.
