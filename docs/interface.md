# Интерфейсный прототип

## Статус и источники

Первый интерфейс predel опирается на [ТЗ](specifications/ФСП%20спец.%20трек%20ТЗ.pdf) и продуктовые документы этого репозитория. Его задача — показать основные сценарии и визуальный подход. Полная готовность MVP и проведённая валидация не заявляются.

Архив `backend.zip`, предоставленный отдельно на рабочем столе, содержит FastAPI-сервис генерации презентаций: загрузку шаблонов, задания сборки, превью и экспорт через `/v2/templates` и `/v2/decks`. В нём нет API профилей кандидатов, тестирования и подбора. Для интерфейса переиспользованы его React-зависимости, lockfile, TypeScript-настройки, локальные шрифты и дизайн главной страницы с оригинальным изображением брелоков. Сохранены плавающая шапка, композиция, синий акцент, анимации и адаптивные размеры; тексты и примеры заменены на сценарии подбора специалистов. Сам презентационный backend не включён.

Логотип ФСП извлечён из `ppt/media/image9.png`, а полоса партнёрских логотипов — из верхней части `ppt/media/image11.png` предоставленного [шаблона презентации](specifications/ЛЦТ_2026_Шаблон%20презентации%20ФСП.pptx). Состав и пропорции логотипов сохранены.

## Что можно проверить

| Сценарий | Поведение интерфейса |
| --- | --- |
| Главная | На `/` показана главная из архива; «Попробовать» открывает подбор на `/app`, «Кандидату» — анкету нового кандидата; логотип кабинета возвращает на главную |
| Быстрый старт | Запрос из формы на главной переносится в поиск работодателя; работают переходы назад и вперёд в браузере |
| Потребность работодателя | Запрос по направлению, грейду и поддерживаемому стеку; произвольный текст ищется по словам в открытых полях профиля |
| Категории | Frontend и Backend, Junior и Middle; выдача использует подтверждённую категорию |
| Подбор | Фильтры по специализации, грейду, стеку, формату и достижениям ФСП; причина попадания в выдачу открывается значком рядом с баллом |
| Ранжирование | После обязательных фильтров используются результат теста и ограниченный бонус за демонстрационную историю ФСП |
| Сохранение | До десяти именованных подборок; текущие запрос и фильтры сохраняются при переходе между вкладками |
| Первый путь кандидата | Обязательная анкета → тест → категория; переход по прямой ссылке не позволяет пропустить анкету |
| Анкета | Имя, email, отрасль, профессиональная роль, специализация, самооценка грейда, стек, опыт и софт-скиллы; согласие на обработку данных и отдельная необязательная публикация |
| Профиль | Ручной ввод, отрасль и роль, софт-скиллы с пометкой самооценки, самооценка грейда отдельно от подтверждённой категории, настройки видимости и согласие |
| PDF-профиль | Предпросмотр и печатная версия; сохранение PDF через стандартный диалог браузера |
| Тест | Программа по специализации и самооценке из анкеты, шесть вопросов; история анкет и попыток сохраняется в браузере |
| Первая категория | Новый профиль не имеет подтверждения и не попадает в подбор до успешного теста; нужны также согласие и включённая публикация |
| Неудачный тест | Первая неудача не присваивает категорию; ранее подтверждённая категория сохраняется |
| Смена категории | Успешная проверка другого грейда или специализации; интервал 90 дней отсчитывается после первого подтверждения, повтор того же теста разрешён |
| ФСП | Показ демонстрационных достижений и пустой истории; ввод ID не присваивает подтверждение |
| Приглашение | Компания, предложение, условия, контакт работодателя и обязательная положительная вилка зарплаты в рублях |
| Контакты | В интерфейсе скрыты до принятия приглашения этой компании; просмотр и отказ не открывают контакты |
| Статусы | Отправлено, просмотрено, принято и отклонено; одинаковое состояние в двух кабинетах |

## Тестирование и данные

У каждой из четырёх программ есть три темы с тремя вопросами на тему. В попытку выбираются по два вопроса каждой темы; порядок вопросов и ответов меняется. Порог 70/100 и программа показаны до начала теста. Это демонстрационная механика, а не валидированная процедура оценки профессионального грейда.

В стартовых данных есть шесть синтетических кандидатов с завершённой оценкой, демонстрационная компания и достижения. Собственный профиль начинает без подтверждённого грейда, приглашений и истории тестов. После заполнения анкеты результаты отражают только прохождение демонстрационных вопросов и не являются реальной валидацией грейда. Софт-скиллы остаются самооценкой. В рабочей версии вопросный банк, правильные ответы и проверка должны находиться на сервере; сопоставимость вариантов необходимо проверить по [плану валидации](metrics_and_validation.md).

Общее состояние хранится в `localStorage`, текущий поиск — в `sessionStorage`. При обновлении формата сохранённых данных прежние правки и пользовательская история сохраняются; предзаполненные тест и приглашение удаляются. Открытые вкладки одного браузера синхронизируют состояние. Анкета создаёт локальный профиль, не аккаунт: введённый email не подтверждается, другой браузер или устройство не получает эти данные. Переключатель роли служит демонстрации и не является системой авторизации.

## Следующий этап

Для рабочего MVP нужны API и серверное разграничение прав: регистрация с подтверждением email, профили, задания и оценивание, приглашения, хранение согласий и результатов, безопасное раскрытие контактов. Ограничения доступа сейчас применяются только в интерфейсе на синтетических данных и не обеспечивают защиты данных в браузере.

Подключение реестра ФСП не имитируется успешным ответом: введённый ID ожидает проверки. Публикация вакансий, самостоятельные отклики и короткие задания работодателей пока не включены, поскольку они относятся к дополнительному объёму.
