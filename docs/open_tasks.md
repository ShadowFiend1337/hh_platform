# Открытые задачи и проверка модератором

Обновлено 11 октября 2026 года. Тест состоит из двух частей. Закрытая часть проверяется автоматически и быстро отсекает тех, кто не готов к грейду. Открытые задачи показывают, как кандидат решает рабочую проблему; их оценивает человек по рубрике.

## Как проходит тест

1. **Закрытая часть** — 12 вопросов, при пройденном впритык пороге ещё 6 уточняющих ([правила](assessment_policy.md)). Если порог не пройден, тест на этом заканчивается: открытые задачи не выдаются и время кандидата не тратится.
2. **Открытые задачи** — 2 практические задачи той же специализации и грейда из [банка кейсов](review-bank/README.md). Ответ — текст, код или SQL до 12 000 символов. Время — из оценки задачи (обычно 15–25 минут). Прокторинг тот же: уходы со страницы, запрет буфера обмена. В поле ответа работают выделение и обычные сочетания клавиш.
3. **Отправка** — закрытая часть посчитана, результат помечен «На проверке». Грейд ещё не подтверждён, но и не провален: ожидания пересдачи нет. Новую попытку на этот же грейд нельзя начать, пока идёт проверка.
4. **Проверка** — модератор ставит по каждому критерию рубрики 0, 1 или 2. Пропущенный или поздний ответ оценивается только нулём. Открытая часть — среднее по задачам, итог — **50% закрытой + 50% открытой части**, порог 70, от 90 баллов открывается следующий грейд.
5. **Итог** — пройденный результат подтверждает грейд в профиле на сервере по обычным правилам (смена категории раз в 90 дней). Комментарии модератора видны кандидату в истории. Если в задаче дефект, модератор аннулирует попытку с причиной: она не засчитывается и не блокирует пересдачу.

Число открытых задач задаёт `ASSESSMENT_OPEN_TASKS` (0–3, по умолчанию 2). При `0` тест состоит только из закрытой части и подтверждает грейд сразу.

## Подбор задач

- Банк: 165 открытых кейсов, по 33 компетенции на каждый грейд. Сложность растёт от стажёра к лиду внутри каждой компетенции, поэтому задача выбирается строго под грейд, а не «полегче» или «посложнее».
- Порядок: сначала кейсы, которых кандидат ещё не видел; затем совпадение с его стеком и навыками вакансии; затем задачи до 25 минут. Две задачи — из разных компетенций.

## Генерация: похожая задача, а не новые числа

Задача выдаётся как авторский кейс или как **сгенерированный вариант** этого кейса. Вариант создаёт открытая Qwen одним запросом по «паспорту» кейса ([генератор](review-bank/generation.md)). Модель переносит замысел и путь решения, а не подставляет числа. Обязательно меняются представление данных и постановка вопроса, ещё минимум одно измерение из предметной области и ограничений. Проверяемые операции, типичные ошибки и объём работы сохраняются. Варианты, отличающиеся от существующих только числами, отклоняются автоматически: тексты сравниваются с числами, заменёнными на `#`. Та же проверка добавлена в генератор закрытых вопросов.

Варианты копятся в пуле в фоне — до 3 на кейс и не больше 12 вызовов модели в час. Старт попытки не ждёт модель. Без ключа OpenRouter выдаются авторские кейсы, и тест работает полностью. Модератор видит, какая задача авторская, а какая сгенерирована: модель, исходный кейс, список изменений и обоснование, почему путь решения тот же.

## Кабинет модератора

`/moderation` → вкладка **«Тесты»**: очередь «На проверке / Проверено / Аннулировано» и карточка попытки.

- Сводка: закрытая часть, открытая часть, итог с прогнозом «пройдёт / не пройдёт» по мере выставления оценок, уходы со страницы и попытки копирования.
- Открытые задачи: условие, происхождение, ответ кандидата, эталон и типичные ошибки, рубрика с пояснением каждого балла, комментарий к задаче.
- **ИИ-подсказка оценок**: открытая модель предлагает баллы по рубрике с обоснованием; в модель не передаются имя и контакты, текст ответа помечен как данные. Решение всегда за модератором.
- Закрытая часть: каждый вопрос, ответ кандидата и ключ, пилотные вопросы, происхождение (авторский или сгенерированный, генератор, решатель, уверенность решателя).

**Тестовый модератор** `local_moderator` (пароль на странице входа) сразу открывает `/moderation#tests`. В очереди уже есть попытка тестового кандидата: закрытая часть 83/100 и два ответа — полный и частичный. Тестовый модератор видит только тестовые аккаунты. Заявки на достижения с личными документами ему недоступны. Реальному модератору право выдаётся командой `npm run moderator -- grant <логин>`. Он видит только реальные аккаунты и никогда — свои попытки.

## API

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/assessment/attempts/{id}/answer` | `{ token, questionId, answerText }` для открытой задачи |
| `GET` | `/api/moderation/assessments?status=pending` | Очередь |
| `GET` | `/api/moderation/assessments/{id}` | Ответы, ключи, рубрики, происхождение |
| `POST` | `/api/moderation/assessments/{id}/ai-review` | Подсказка оценок |
| `POST` | `/api/moderation/assessments/{id}/decision` | `{ version, decision: grade \| invalidate, note, marks }` |

Полное описание — в [OpenAPI](api/platform.openapi.json) и Swagger UI `/api/docs`.

## Проверки

`npm run test:open-assessment`:

- **сервер** — порядок этапов; ключи и рубрики не уходят кандидату; блокировка повторной попытки на время проверки; расчёт 50/50; подтверждение грейда на сервере; изоляция тестового и реального модератора; ИИ-подсказка без персональных данных; задачи под грейд без повторов;
- **браузер** — полный цикл кандидат → модератор → профиль и вход тестового модератора со страницы входа.

Ограничения: сложность вариантов не измерена на людях. Структурные проверки генератора не доказывают равную сложность — это задача пилота и экспертной проверки. Время на открытые задачи — оценка авторов банка.
