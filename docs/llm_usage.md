# Использование LLM

Организаторы разрешают облачные LLM, включая зарубежные, и предпочитают открытые модели с адекватным числом параметров (VS.3); использование нужно описать. В проекте допускаются только модели с опубликованными весами, доступ — через OpenRouter, оплата — на стороне команды. GPU на стенде не нужен.

| Где | Модель | Что передаётся | Зачем |
| --- | --- | --- | --- |
| Генерация тестовых заданий ([dynamic_bank.md](dynamic_bank.md)) | `qwen/qwen3-30b-a3b-instruct-2507` (Apache-2.0), резерв `qwen/qwen3-32b` | Тема, навыки, описание грейда, авторские образцы семейства, сценарии открытого банка | Пополнение пула эквивалентных заданий |
| Независимая проверка сгенерированных заданий | `deepseek/deepseek-v3.2` (MIT) | Только текст вопроса и перемешанные варианты | Задание допускается, лишь если другая модель решает его по ключу |
| Авторская проверка открытых ответов ([openrouter_assessment.md](openrouter_assessment.md)) | те же открытые модели | Задание, рубрика, обезличенный ответ | Черновая проверка рубрик; на грейд не влияет |

Принципы:

- **Персональные данные не передаются.** В запросах нет ФИО, контактов, резюме и идентификаторов аккаунтов; трансграничной передачи ПДн (152-ФЗ) нет. Для провайдеров включено `data_collection: deny`.
- **LLM не присваивает грейд.** Балл считает сервер по ключам; сгенерированное задание идёт в зачёт только после пилота и калибровки или одобрения эксперта.
- **Без ключа всё работает:** тест использует авторский банк и уже накопленные задания.
- Допускаются только идентификаторы `qwen/*` и `deepseek/*`; другие отклоняются при запуске.

Настройка (`.env`, не коммитится):

```dotenv
OPENROUTER_API_KEY=<ключ>
OPENROUTER_MODEL=qwen/qwen3-30b-a3b-instruct-2507
OPENROUTER_FALLBACK_MODEL=qwen/qwen3-32b
OPENROUTER_VERIFIER_MODEL=deepseek/deepseek-v3.2
ITEM_BANK_AUTOGEN=1
```

Клиент: [server/llm.mjs](../server/llm.mjs) — таймаут 25 с, один повтор на 429/5xx, тело ошибки провайдера не читается и не логируется, учёт токенов. Проверки: `node --test server/tests/llm.test.mjs`.
