# Использование LLM

Организаторы разрешают облачные LLM, включая зарубежные, и предпочитают открытые модели с адекватным числом параметров (VS.3); использование нужно описать. В проекте допускаются только модели с опубликованными весами, доступ — через OpenRouter, оплата — на стороне команды. GPU на стенде не нужен.

| Где | Модель | Что передаётся | Зачем |
| --- | --- | --- | --- |
| ИИ-помощники кандидата и работодателя (см. ниже) | `qwen/qwen3-30b-a3b-instruct-2507`, резерв `qwen/qwen3-32b` | Вопрос, до 8 последних реплик, раздел кабинета, обезличенный контекст | Навигация по платформе, подготовка профиля, запрос для поиска, текст приглашения |
| Генерация тестовых заданий ([dynamic_bank.md](dynamic_bank.md)) | `qwen/qwen3-30b-a3b-instruct-2507` (Apache-2.0), резерв `qwen/qwen3-32b` | Тема, навыки, описание грейда, авторские образцы семейства, сценарии открытого банка | Пополнение пула эквивалентных заданий |
| Независимая проверка сгенерированных заданий | `deepseek/deepseek-v3.2` (MIT) | Только текст вопроса и перемешанные варианты | Задание допускается, лишь если другая модель решает его по ключу |
| Авторская проверка открытых ответов ([openrouter_assessment.md](openrouter_assessment.md)) | те же открытые модели | Задание, рубрика, обезличенный ответ | Черновая проверка рубрик; на грейд не влияет |
| Переработка неверных вариантов авторского банка ([bank_quality.md](bank_quality.md)), офлайн, `scripts/revise-distractors.mjs` | Генерация — `deepseek/deepseek-v3.2`; два судьи — `openai/gpt-oss-120b` (Apache-2.0) и `deepseek/deepseek-v3.2`; проверка без условия — `openai/gpt-oss-120b` | Условие, правильный ответ и варианты; без данных кандидатов | Правдоподобные неверные варианты вместо очевидных; приняты, только если оба судьи признают ключ верным, а каждый новый вариант — неверным |
| Оценка практических задач теста ([open_tasks.md](open_tasks.md)) | Две независимые модели параллельно: `qwen/qwen3-30b-a3b-instruct-2507` и `deepseek/deepseek-v3.2` | Условие, рубрика, эталон, обезличенный ответ | Баллы 0–2 по критериям с дословной цитатой из ответа; при согласии — среднее, половина итога; при расхождении или манипуляции — эксперт |

Принципы:

- **Персональные данные не передаются.** В запросах нет ФИО, контактов, резюме и идентификаторов аккаунтов; трансграничной передачи ПДн (152-ФЗ) нет. Для провайдеров включено `data_collection: deny`.
- **LLM не присваивает грейд сама.** Закрытую часть сервер считает по ключам; модель ставит только баллы по критериям рубрики практики, а итог 50/50 и порог считает сервер. Каждый балл модель подтверждает дословной цитатой из ответа, сервер проверяет её наличие; балл без цитаты не засчитывается. Две модели оценивают независимо, расхождение на 2 балла или в вердикте и попытка повлиять на проверку отправляют попытку эксперту. Неполный ответ модели не засчитывается, эксперт может перепроверить любую оценку. Сгенерированное задание идёт в зачёт только после пилота и калибровки или одобрения эксперта.
- **Без ключа всё работает:** тест использует авторский банк и уже накопленные задания, а при недоступной модели практику оценивает эксперт; до его решения грейд не подтверждается.
- Допускаются только идентификаторы `qwen/*` и `deepseek/*`; другие отклоняются при запуске.

## ИИ-помощники

Два разных помощника с отдельными серверными промптами ([server/assistant.mjs](../server/assistant.mjs)):

| | Карьерный помощник (кандидат) | Помощник по подбору (работодатель) |
| --- | --- | --- |
| Задачи | Что заполнить в профиле, правила теста и пересдачи, приглашения и отклики, привязка ФСП, советы по описанию опыта | Поисковый запрос и фильтры, категории, процент совпадения и объяснение выдачи, текст приглашения с вилкой зарплаты, вакансии |
| Контекст | Процент готовности профиля, чего не хватает, подтверждён ли грейд, специализация и грейд, число новых приглашений | Число потребностей, ожидающих и принятых приглашений |
| Ограничения | Не решает вопросы теста: сообщения, похожие на вопрос теста с вариантами, отвечаются отказом без обращения к модели; во время активной попытки сервер отвечает `409` | Не называет рыночные зарплаты как факт, не обещает контакты до принятия приглашения |

Общее: ответ строго на «вы», только факты о платформе из промпта, ссылки только на разделы своей роли (формат `[Название](#ключ)` превращается в кнопки перехода, внешние адреса вырезаются), отказ на посторонние темы. Имена, контакты, тексты резюме и вопросы теста в модель не передаются; контекст фильтруется по списку разрешённых полей. Без ключа или при сбое модели работают готовые подсказки по ключевым словам. Лимит — 20 сообщений за 10 минут на аккаунт; ответ в среднем 5–10 секунд, около $0,0004 за сообщение.

API: `GET /api/assistant/info` и `POST /api/assistant/chat` с `{ message, page, history, context }` → `{ reply, links, source }`. Проверки: `node --test server/tests/assistant.test.mjs`.

## Прокси

Если openrouter.ai недоступен напрямую, задайте в `.env` `HTTPS_PROXY` (и `NO_PROXY=localhost,127.0.0.1,::1`). Сервер и `npm run bank:*` применяют прокси после чтения `.env` (`server/proxy.mjs`).

Настройка (`.env`, не коммитится):

```dotenv
OPENROUTER_API_KEY=<ключ>
OPENROUTER_MODEL=qwen/qwen3-30b-a3b-instruct-2507
OPENROUTER_FALLBACK_MODEL=qwen/qwen3-32b
OPENROUTER_VERIFIER_MODEL=deepseek/deepseek-v3.2
ITEM_BANK_AUTOGEN=1
```

Клиент: [server/llm.mjs](../server/llm.mjs) — таймаут 25 с, один повтор на 429/5xx, тело ошибки провайдера не читается и не логируется, учёт токенов. Проверки: `node --test server/tests/llm.test.mjs`.
