# Вход через ФСП ID

ТЗ: профиль кандидата должен связываться с ID участника ФСП; ФСП ID будет работать на Keycloak, совместимость приветствуется. Ответы организаторов: боевых доступов не будет, стоит имитировать вход через FSP ID и сделать скелет интеграции на своих данных.

## Как работает

Платформа — клиент OpenID Connect (как к любому Keycloak): authorization code flow + PKCE S256, `state` в короткой HttpOnly-cookie, `nonce` в ID-токене.

1. «Войти через ФСП ID» → `GET /api/auth/fsp/start` → перенаправление на `…/realms/fsp/protocol/openid-connect/auth`.
2. Участник входит в ФСП ID и разрешает доступ к ФИО, e-mail и результатам (`scope=openid email profile fsp_achievements`).
3. `GET /api/auth/fsp/callback?code&state` — обмен кода на токены, проверка подписи и `nonce`, получение профиля участника.
4. Если учётная запись ФСП уже привязана — сразу вход. Если аккаунта нет — экран завершения: данные из ФСП ID, логин, согласие на обработку ПДн (`POST /api/auth/fsp/complete`). Почту подтвердил ФСП ID, код не нужен. Если такая почта уже зарегистрирована паролем, автоматической привязки нет: нужно войти паролем (защита от захвата аккаунта).
5. Результаты соревнований сразу попадают в профиль с пометкой источника; отсутствие истории ФСП обрабатывается штатно. Грейд по-прежнему подтверждается только тестом.

## Тестовый стенд

Без настроек работает встроенная имитация realm `fsp` с вымышленными участниками: победитель Чемпионата России (продуктовое программирование), призёр Кубка (алгоритмическое), финалист по ИБ и новый участник без результатов. Эндпоинты имитации повторяют Keycloak: `/.well-known/openid-configuration`, `/protocol/openid-connect/auth|token|userinfo`. В production имитация выключена.

## Подключение настоящего Keycloak

```dotenv
FSP_ID_ISSUER=https://id.fsp.example/realms/fsp
FSP_ID_CLIENT_ID=predel
FSP_ID_CLIENT_SECRET=<секрет клиента>
FSP_ID_REDIRECT_URI=https://predel.example/api/auth/fsp/callback
```

Код тот же: меняются только адреса. Профиль берётся из `userinfo`; поле с результатами (`fsp_achievements`) — предложение к будущему контракту ФСП ([контракт ресурсов](api/fsp-provider.openapi.json)).

Реализация: [server/fsp-id.mjs](../server/fsp-id.mjs), привязка аккаунтов — таблица `auth_federated_identities`. Проверки: `node --test server/tests/fsp-id.test.mjs` (PKCE-поток, импорт достижений, повторный вход, подделка `state`, отказ участника, участник без истории, выключение в production).
