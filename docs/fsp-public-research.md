# Публичные источники ФСП: исследование и работающий пилот

Проверено 7 октября 2026 года. Без учётных данных ФСП доступны опубликованные результаты соревнований. Публичного документированного API достижений в проверенных ресурсах не найдено; это не доказывает, что его нет у Федерации.

## Что найдено

- [Официальный сайт](https://fsp-russia.ru/) и [раздел документов](https://fsp-russia.ru/about/documents/). В разделе обнаружены 16 уникальных ссылок на PDF протоколов и турнирных таблиц за 2025–2026 годы. Это список документов, а не 16 уже импортированных соревнований: некоторые PDF содержат также справки, результаты команд без состава или несколько протоколов.
- [Личный кабинет спортсмена](https://lk.fsp-russia.ru/login). Публичная ссылка входа переводит на Keycloak / OpenID Connect.
- Настоящий issuer: `https://sso.fsp-russia.ru/realms/fsp`. [Discovery](https://sso.fsp-russia.ru/realms/fsp/.well-known/openid-configuration) отвечает JSON, поддерживает PKCE S256 и `client_secret_post`. Указанный в нашем проектном контракте scope `fsp:achievements:read` в опубликованном `scopes_supported` не найден. Discovery не раскрывает API достижений и не даёт нашему приложению регистрацию клиента.
- [Финальный протокол Кубка России 2025, алгоритмическое программирование](https://fsp-russia.ru/upload/iblock/2fd/go7v4ekr13s1wwepx7poocbxgxd2u92i.pdf): две страницы, 24 индивидуальных результата, дата результата 25 мая 2025 года. Столбцы: место, участник, решённые задачи, время выполнения задач, субъект. Единица времени в заголовке не указана, сохраняется исходное число.
- [Продуктовое программирование](https://fsp-russia.ru/upload/iblock/f5e/8ma6l935b05m4q88wi5n24ne23p7qbya.pdf) и [информационная безопасность](https://fsp-russia.ru/upload/iblock/64f/we0j21ozoe17st1y8sco3sn04z4e9eui.pdf): командные результаты, отдельные роли спортсменов и тренеров. В пилотный каталог не включены. Будущий парсер должен сохранять эти роли и учитывать продолжения команды на следующей странице.

Найденный поиском `fsp-platform.ru` описывался как разработка команды DAVG в рамках соревнований 2025 года. Его принадлежность к рабочей инфраструктуре Федерации не установлена; он не используется как доверенный источник.

Список найденных документов с исходными URL: [fsp-public-sources.json](api/fsp-public-sources.json).

## Реализованный путь без доступа к API ФСП

Публичный PDF → разбор строк и ячеек → OCR → отчёт для проверки → проверенный снимок → поиск по ФИО в нашем API.

```sh
# Нужны frontend-зависимости и локальные языковые модели, которые готовит npm ci --prefix frontend.
npm run import:fsp-public -- --discover
npm run import:fsp-public
# Повторить OCR ранее скачанного файла без сети:
npm run import:fsp-public -- --cached
```

Импортёр скачивает только фиксированный официальный URL; произвольный адрес от пользователя не принимается. Он ограничивает размер файла, время запроса и запрещает редиректы. OCR работает локально через уже используемые проектом PDF.js и Tesseract.js; документы не передаются внешнему AI-сервису. Результаты и PNG страниц находятся в игнорируемом `server/data/fsp-public/`.

Парсер первой версии поддерживает только указанный двухстраничный протокол алгоритмического финала. Он определяет границы строк по сетке таблицы, распознаёт ячейки отдельно и проверяет последовательность мест, числа и формат ФИО. Изменение числа страниц/строк или нечитабельная ячейка останавливает импорт. Распознаваемые строки всегда получают `extractionStatus=needs_review`: confidence OCR не заменяет проверку.

Включённый в репозиторий каталог `server/integrations/data/fsp-public.json` содержит 24 записи, сверенные с обеими страницами оригинала. Для публикации другого снимка нужно визуально проверить все имена/числа/регионы, исправить ошибки OCR, указать дату проверки источника и `extractionStatus=reviewed`, затем атомарно заменить этот файл. Импортёр самостоятельно этого не делает. Сервер откажет в выдаче снимка с непроверенными строками. SHA-256 PDF и страницы каждой записи позволяют повторить сверку; новый хеш документа требует новой проверки.

## Контракт нашего API

`GET /api/integrations/fsp-public/search?name=Ромашов%20Федор&limit=20&offset=0`

Требуется сессия кандидата и сохранённое согласие профиля. Слова фамилии/имени указываются полностью; порядок, регистр и ё/е не важны. Лимит: 30 запросов в минуту на аккаунт, до 50 результатов на страницу. Полная схема находится в [integrations.openapi.json](api/integrations.openapi.json).

Ответ содержит сведения об участии, `sourceUrl`, `sourcePage`, `documentHash`, даты загрузки/проверки, объём текущего каталога. `coverage.complete=false`: отсутствие совпадений ничего не говорит о всей истории спортсмена. Поиск также доступен в профиле в разделе «Внешние подтверждения → Публичные протоколы ФСП».

Каждый результат имеет `status=unverified`, `identityVerified=false`. В протоколе нет проверенного идентификатора аккаунта кандидата. Совпадение ФИО, даже с регионом, не устанавливает принадлежность записи конкретному человеку. Поиск не создаёт подключение или доказательство профиля, не меняет фильтр/бонус ФСП, грейд или результаты тестирования.

Процедура [проверки принадлежности и модерации](achievement-moderation.md) реализована: кандидат отправляет материалы, модератор принимает решение, после одобрения появляется отдельное серверное доказательство. Результаты самого поиска по-прежнему остаются `unverified`. Вход через ФСП ID потребует регистрации нашего клиента; одного входа недостаточно, если нет доверенного соответствия между subject ФСП ID и записью протокола. До появления такого соответствия возможна отдельная модерация подтверждающих документов. Согласовывать весь ресурсный API для запуска пилота не требуется.
