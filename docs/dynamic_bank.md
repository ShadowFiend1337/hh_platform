# Динамический банк заданий

Обновлено 9 октября 2026 года. ТЗ требует механику, устойчивую к распространению заданий, при сопоставимой сложности для разных кандидатов. Единый набор быстро разойдётся, а генерация уникального теста нейросетью под каждого кандидата не гарантирует равной сложности. Поэтому решение сочетает **авторский банк**, **пул сгенерированных клонов семейств** и **статистическую калибровку перед зачётом**.

## Структура теста

- Программа = специализация × грейд (14 × 5 = 70 программ), 3 темы, в каждой теме два семейства: базовый и повышенный слот сложности.
- **Семейство** — модель задания: тема, слот сложности, проверяемые навыки и несколько эквивалентных вариантов. Авторских вариантов в банке 1680 (по 4 на семейство).
- Попытка: из каждого семейства 2 зачётных задания → **12 зачётных вопросов** (4 на тему, 6 базовых и 6 повышенных) + до **1 пилотного** незачётного вопроса. Порог — 70/100 (9 из 12).
- Состав (темы, слоты, число вопросов, порог) одинаков для всех кандидатов грейда; меняется только то, **какие эквивалентные задания** выпадают.
- Если первые 12 вопросов дают порог пройден впритык (9 верных из 12, балл 70–79), добавляется **уточняющий блок** из 6 свежих заданий тех же семейств; решение принимается по 18 вопросам. Перепроверка прошедших впритык снижает в модели долю ошибочных подтверждений грейда ([результаты](assessment_validation_results.md)).

## Выбор заданий

1. Пул семейства = авторские варианты + одобренные сгенерированные (`active`).
2. Задания, которые этот кандидат уже видел в последних попытках, исключаются, пока есть свежие.
3. Если указано описание вакансии, сначала берутся варианты с совпадающими навыками.
4. Внутри уровня релевантности выбор случайный с весом `1 / (1 + показы/10)`: редко показанные задания выпадают чаще, ответы на «популярные» задания теряют ценность.
5. Сгенерированное задание выводится из оборота после 150 показов (могло разойтись). Задание и его клон не попадают в одну попытку.

## Генерация (как «кормится» нейросеть)

Генератор (`server/item-generator.mjs`) получает:

- тему, слот сложности, описание грейда и список навыков семейства;
- 3 авторских задания семейства как образцы уровня и формата (копировать запрещено);
- 2 сценария из собранного открытого банка задач по специализации (`server/open-bank/*`) как предметный контекст;
- последние тексты семейства, чтобы не повторяться.

Модель пишет новые рабочие ситуации с 4 вариантами и одним правильным ответом. Персональные данные в запрос не передаются.

### Проверка перед допуском

1. **Локальные проверки:** 4 различных варианта; та же проверка подсказок, что у переработанного авторского банка ([bank_quality.md](bank_quality.md)): длины неверных вариантов в диапазоне от длины ключа, ключ не длиннее всех, нет «всегда»/«никогда»/«любой»/«все перечисленное»/«ни один из»; условие не содержит ответ, нет e-mail/телефонов, нет перефразированного дубликата (сходство по словам < 0,55), уникальный отпечаток.
2. **Независимый решатель:** другая модель (DeepSeek) решает вопрос с перемешанными вариантами без ключа. Задание принимается, только если она выбрала ключевой ответ, не сочла вопрос двусмысленным и уверена не менее чем на 0,6.
3. **Проверка без условия:** модель видит только перемешанные варианты, без вопроса. Если она находит ключ, вариант выдаёт себя видом — задание отклоняется.
4. Принятое задание получает статус **`pilot`**.

## Жизненный цикл

| Статус | Что значит |
| --- | --- |
| `pilot` | Показывается как 13-й, **незачётный** вопрос (не первым, неотличим для кандидата). Собирает статистику, на балл не влияет. |
| `active` | Зачётное задание. Переход из пилота: эксперт одобрил в модерации **или** набралось ≥ 12 ответов, доля верных в пределах ±0,25 от эталона семейства и точечно-бисериальная корреляция с итоговым баллом неотрицательна. |
| `retired` | Не прошло калибровку, превысило 150 показов или показало отрицательную дискриминацию после 40 ответов (сильные кандидаты ошибаются чаще). |
| `rejected` | Отклонено экспертом. |

Эталон сложности семейства — доля верных ответов авторских заданий (когда по ним ≥ 12 ответов), иначе априорное значение: 0,72 для базового и 0,55 для повышенного слота. Так сгенерированные задания попадают в зачёт только с подтверждённой сопоставимой сложностью — ответ на главное возражение ТЗ к генерации нейросетью.

## Модели и стоимость

Только открытые модели через OpenRouter (организаторы предпочитают открытые, VS.3):

| Назначение | Модель по умолчанию | Лицензия весов |
| --- | --- | --- |
| Генерация заданий | `qwen/qwen3-30b-a3b-instruct-2507` (резерв `qwen/qwen3-32b`) | Apache-2.0 |
| Независимый решатель | `deepseek/deepseek-v3.2` | MIT |

Цена на 9 октября 2026 года: Qwen3-30B-A3B — $0,10 / $0,30 за 1 млн входных/выходных токенов, DeepSeek V3.2 — $0,26 / $0,42. Одно семейство (3 задания + 3 проверки) — около 6–8 тыс. токенов, т. е. доли цента. Без ключа платформа работает на авторском банке и уже накопленном пуле.

## Как пользоваться

```bash
npm run bank:stats
npm run bank:generate -- --specialization Backend --grade Middle --per-family 3
npm run bank:generate -- --all --per-family 2
npm run bank:list -- --status pilot --specialization Backend --grade Middle
node scripts/item-bank.mjs approve <id>
```

Ключ задаётся в `.env`: `OPENROUTER_API_KEY=...`. При `ITEM_BANK_AUTOGEN=1` сервер сам пополняет семейства, в которых осталось меньше 10 доступных заданий (не более 24 семейств в час, по одному за раз, в фоне — старт попытки не ждёт генерацию).

Модератор (отдельный аккаунт, создаётся `npm run moderator -- create <логин> <почта>`) работает в своём кабинете, раздел **«Банк заданий»** (`/moderation#bank`): фильтры по специализации, грейду и статусу, сводка банка и состояния генератора, текст задания с ключом и пояснением, решение независимого решателя, статистика показов и ответов, кнопки «В зачёт» и «Отклонить» для пилотных заданий, запуск генерации для выбранной программы. Те же действия доступны через API:

- `GET /api/item-bank/items?specialization=&grade=&status=` — задания, статистика показов/ответов, сводка, состояние генератора;
- `POST /api/item-bank/items/{id}/review` с `{ "decision": "approve" | "reject", "note": "..." }`;
- `POST /api/item-bank/generate` с `{ "specialization": "Backend", "grade": "Middle" }` — поставить программу в очередь генерации.

## Проверки

`npm run test:item-bank-ui` — страница модерации банка в браузере: работодателю закрыта, ключ виден модератору, одобрение переводит задание в зачёт, отклонение убирает его из пилота.

`node --test server/tests/item-bank.test.mjs`: пилот не влияет на балл и не идёт первым; одобрение экспертом вводит задание в зачёт; калибровка продвигает подходящее и выводит неподходящее; вывод после лимита показов; предпочтение редко показанных; локальные проверки; генерация с решателем на mock-модели (принято только то, что решатель решил по ключу; в запросе есть авторские образцы и сценарии открытого банка, нет персональных данных).
