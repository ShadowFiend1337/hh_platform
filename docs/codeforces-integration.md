# Подтверждение достижений Codeforces

Первый внешний источник помимо ФСП: публичный официальный API Codeforces. Реализованы подключение аккаунта без пароля, автоматическая загрузка результатов, повторная синхронизация и отключение. Это основной Node.js backend; FastAPI эти маршруты не обслуживает.

## Что именно подтверждается

Проверки разделены: источник сообщает факт результата, а одноразовый код доказывает контроль над аккаунтом на момент привязки. Ни контроль аккаунта, ни вердикт `OK` не подтверждают паспортную личность или отсутствие списывания. Профессиональный грейд определяется тестированием платформы. Данные Codeforces не включают фильтр «достижения ФСП» и не начисляют бонус ФСП.

Источники: [официальное описание методов](https://codeforces.com/apiHelp/methods?locale=en&mobile=true), [структуры данных](https://codeforces.com/apiHelp/objects?locale=en), [лимиты API](https://codeforces.com/apiHelp/?locale=ru&mobile=true).

## Путь кандидата

1. Сохранить профиль с согласием на обработку данных; в «Внешних подтверждениях» отдельно согласиться на получение достижений.
2. Указать ник Codeforces и нажать «Подключить Codeforces».
3. Сохранить прежнее значение Organization / Организация в настройках Codeforces, временно заменить его выданным кодом `predel-…` и сохранить профиль.
4. Нажать «Я сохранил код — проверить». Код должен быть полным значением поля Organization, без дополнительных слов. Код действует 30 минут, привязан к кандидату, нику и времени регистрации аккаунта; успешная проверка однократна.
5. После подтверждения вернуть прежнюю организацию. Код для последующих синхронизаций не требуется.

Старт новой проверки заменяет предыдущую; «Отменить подключение» удаляет ожидающую проверку. Один внешний аккаунт нельзя одновременно связать с двумя кандидатами. При смене ника/времени регистрации повторная загрузка требует нового подтверждения, а не угадывает новый аккаунт по ФИО. Для защиты от подмены исторический поиск ников выключен.

## Импорт и ограничения

- `user.info`: текущий/максимальный рейтинг, ник и время регистрации. Контактные поля не сохраняются и не публикуются.
- `user.rating`: до 1000 последних рейтинговых выступлений. Место обозначено как **место при пересчёте рейтинга**; `place=null`, поскольку API предупреждает, что это значение не меняется после дальнейших изменений таблицы/дисквалификаций. Это не гарантия текущего итогового места.
- `user.status`: до 2000 последних отправок, 8 страниц по 250. Уникальные задачи считаются по идентификатору соревнования/набора и индексу задачи; повторные успешные отправки не увеличивают число. Командные решения исключаются. Practice/виртуальные решения могут входить в число принятых решений, но не объявляются турнирными местами.
- При достижении лимита выборка явно помечена как ограниченная, без утверждения об общем числе задач за всё время. Пустая история не создаёт вымышленных достижений.
- На каждую запись сохраняются ссылка источника, дата, хеш снимка, способ подтверждения `profile_challenge` и версия правил `codeforces-algorithms-v1`. Направления «Алгоритмы»/«Структуры данных» — сведения для оценки кандидата, не сертификат владения конкретным стеком.

Общая очередь адаптера выдерживает минимум 2,1 секунды между запросами. Не более 20 ожидающих сетевых запросов; переполнение и upstream rate limit считаются временными ошибками. Каждый HTTP-запрос ограничен 10 секундами и 1 МБ JSON, редиректы запрещены. Снимок заменяется атомарно только после полного успешного импорта; пропавшие записи отзываются. При сбое прежние записи показываются как требующие обновления. Повторная синхронизация запускается примерно раз в сутки; актуальность подтверждения — 7 дней.

Публичный код в Organization подтверждает контроль аккаунта в конкретный момент; продажу/совместное использование аккаунтов он не обнаруживает. При необходимости более строгой политики можно периодически требовать новое подтверждение. Весь сквозной сценарий проверяется на изолированных данных; проверка реального владения требует действий владельца аккаунта на Codeforces.

## Контракт и конфигурация

Контракт: [OpenAPI 1.3.0](api/integrations.openapi.json).

```http
POST /api/integrations/codeforces/connect
X-Platform-Identity: auth:<account.id>
Content-Type: application/json

{"consent":true,"handle":"YourHandle"}
```

Ответ `202`: `challenge={id,token,handle,field,profileUrl,expiresAt}`; `connection`, `job`, `authorizationUrl` пока `null`. Никаких подтверждённых результатов до проверки не создаётся.

```http
POST /api/integrations/codeforces/verify
X-Platform-Identity: auth:<account.id>
Content-Type: application/json

{"challengeId":"<id из первого ответа>"}
```

Ответ `200`: подключение и фоновая задача. Далее используются общие `GET /api/integration-jobs/{id}`, `GET /api/profile/evidence`, `POST /api/integrations/codeforces/sync` с `{}` и `DELETE /api/integrations/codeforces`. Нужна действующая сессия кандидата; просматривать чужие проверки нельзя. Connect/verify — до 10 запросов за 10 минут на владельца.

OAuth-клиент, пароль Codeforces и пользовательские API-ключи не нужны. `CODEFORCES_ENABLED=0` отключает адаптер. Для production задайте стабильный `INTEGRATION_ENCRYPTION_KEY` (64 hex-символа); ожидающие коды и данные подключения шифруются общей системой интеграций. Если Node.js запускается в окружении, где интернет доступен только через `HTTPS_PROXY`, Node.js 24 нужно запускать с `--use-env-proxy` либо `NODE_USE_ENV_PROXY=1`.

Для нескольких экземпляров backend очередь ограничения запросов нужно вынести в общее хранилище. Текущий сервер работает одним процессом.

## Проверка

`server/tests/codeforces.test.mjs` проверяет принадлежность, чужие/повторные/истёкшие коды, смену проверки, двойную привязку, отзыв согласия/отключение во время сети, пагинацию/дедупликацию/командную атрибуцию, исторические места, пустую историю, сбои и отсутствие бонуса ФСП.

`npm run test:codeforces-browser` проверяет интерфейс: сохранение профиля, запуск проверки, отказ без кода, подтверждение, загрузку результатов, просмотр работодателем и удаление подключения. Источник в браузерном тесте — явная изолированная фикстура.
